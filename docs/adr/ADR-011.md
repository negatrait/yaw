# ADR 011: Compile-Time Closed-World SHACL Validation and O(1) Contradiction Caching

**Status:** Accepted\
**Date:** 2026-10-11\
**Amended by:** [ADR-012](ADR-012.md) — §4: external ontology classes get a space-S vector in `entity_vec` (not `leaf_nodes`) and FTS rows in `query_fts`; ambiguous identity (`sh:Warning`) replaces contested alias merges.\
**Governing Canon:** [`FOUNDATIONAL.md §2 (Invariants 4 & 5), §4.3, §4.4, §5.5`](../../FOUNDATIONAL.md), [`docs/rdf-owl-shacl.md`](../rdf-owl-shacl.md), [`docs/adr/ADR-002.md`](ADR-002.md), [`docs/adr/ADR-008.md`](ADR-008.md), [`docs/adr/ADR-010.md`](ADR-010.md)\
**Implementation:** [`src/yaw/ontology/shacl.py`](../../src/yaw/ontology/shacl.py), [`src/yaw/server/daemon.py`](../../src/yaw/server/daemon.py), [`src/yaw/storage/schema.py`](../../src/yaw/storage/schema.py), [`src/yaw/storage/db.py`](../../src/yaw/storage/db.py)

---

### Context & Problem Statement

YAW enforces the **Karpathy LLM-Wiki lifecycle**, wherein continuous human and agent contributions to `vault/raw/` accumulate into an interconnected knowledge graph, punctuated by periodic compilation and dialectical contradiction resolution:

1. **Ingestion Latency Decoupling:** Continuous single-stage ingestion (`src/yaw/indexer/pipeline.py`) processes raw markdown deltas incrementally via CocoIndex. To maintain sub-second streaming throughput per chunk, chunk ingestion cannot execute expensive global RDF graph serialization, OWL 2 RL transitive closure, and pySHACL shape validation on every note write. Doing so incurs $\sim 150{-}500\text{ ms}$ overhead per chunk, stalling ingestion pipelines.
2. **The On-Demand Linting Latency Anti-Pattern:** Historically, `lint_wiki()` executed live in-process pySHACL validation (`validate_wiki_graph()`) on demand every time a client queried the tool. On growing vaults with thousands of nodes and quads, projecting SQLite views to an in-memory `rdflib.ConjunctiveGraph` and traversing declarative shapes requires multi-second compute ($\mathcal{O}(|V| + |E|)$), creating unacceptable latency for conversational MCP agent interactions.
3. **The Epistemic Contradiction Lifecycle:** In Karpathy's LLM-Wiki model, dialectical contradictions (e.g. `causes` vs `prevents`, `supports` vs `refutes`, ambiguous identities with $\ge 2$ unlinked `close_matches` targets) are not fatal compilation errors; they are **epistemic tension signals**. When surfaced, they inform the agent or operator:
   > *"Contradiction detected between Chunk A and Chunk B regarding predicate causes vs prevents — ingest more authoritative literature or author a reconciling note in vault/raw/"*.
4. **The Missing Compile-Time Persistence Invariant:** Because contradictions were previously computed ephemerally during `lint_wiki()` and never persisted in SQLite, the system could neither inspect contradictions in $\mathcal{O}(1)$ time nor track contradiction resolution across compilation epochs.

---

### Decision

We formalize **Compile-Time Closed-World SHACL Validation and $\mathcal{O}(1)$ Contradiction Caching** as an architectural invariant across the compilation, storage, and MCP server layers.

```
   vault/raw/*.md (Continuous Append-Only Ingestion via CocoIndex)
                           │
                           ▼
             leaf_nodes, leaf_relations, note_chunks
                           │
                           ▼
          compile_wiki(force=False) Execution
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
   B-Tree HAC Splitting        validate_wiki_graph_fast(conn)
   (ADR-002 Hub Deepening)     (<200ms Relational Pre-Closure)
             │                           │
             │                           ▼
             │                 compiled_violations Table
             │                 (Dialectical Contradictions & Shapes)
             │                           │
             └─────────────┬─────────────┘
                           ▼
               lint_wiki(query=None | "X")
               (Instantaneous O(1) SQLite Read)
                           │
                           ▼
               Epistemic Prompt to Agent:
         "Ingest resolving sources into vault/raw/"
```

#### 1. Compile-Time Validation Execution in `compile_wiki()`
- During `compile_wiki()`, after SQLite unified views are ensured and the in-memory knowledge base is synchronized, the compilation pipeline executes lean, in-process SHACL validation via `validate_wiki_graph_fast(conn)`:
  - Leverages relational pre-closure in SQLite to avoid DL tableaux reasoning.
  - Operates under Closed-World Assumption (CWA) with Unique Name Assumption (UNA) against `wiki_shapes.ttl`.
  - Executes deterministically in $<200\text{ ms}$.
- Any detected shape violations or dialectical contradictions (`yaw:DialecticalIntegrityShape`, `yaw:ConceptShape`, `yaw:RelationShape`) are extracted into structured violation records.

#### 2. Persistent `compiled_violations` SQLite Table
- Compilation results are committed transactionally to a dedicated SQLite table in `yaw.db`:
```sql
CREATE TABLE IF NOT EXISTS compiled_violations (
    violation_id TEXT PRIMARY KEY,
    focus_node TEXT NOT NULL,
    shape_id TEXT NOT NULL,
    result_path TEXT,
    severity TEXT NOT NULL CHECK(severity IN ('Info', 'Warning', 'Violation')),
    message TEXT NOT NULL,
    source_chunk_id TEXT,
    conflicting_chunk_id TEXT,
    compiled_at REAL NOT NULL DEFAULT (unixepoch())
);

CREATE INDEX IF NOT EXISTS idx_violations_focus ON compiled_violations(focus_node);
CREATE INDEX IF NOT EXISTS idx_violations_shape ON compiled_violations(shape_id);
CREATE INDEX IF NOT EXISTS idx_violations_severity ON compiled_violations(severity);
```
- **Idempotent Re-Compilation:** At the start of each `compile_wiki()` validation phase, previous violations for re-validated scopes are cleanly refreshed, preventing stale orphaned contradiction records.

#### 3. Instantaneous $\mathcal{O}(1)$ Read Contract in `lint_wiki()`
- `@mcp.tool() async def lint_wiki(query: str | None = None, vault_dir: str | None = None, force: bool = False) -> list[dict]`:
  - **Default Mode (`force=False`):** Queries `compiled_violations` directly from SQLite. Execution completes in $\mathcal{O}(1)$ time ($< 5\text{ ms}$).
  - **Scoped Query (`query="<term | URI>"`):** Executes an indexed `WHERE focus_node = ? OR message LIKE ?` lookup, returning localized contradictions for the target concept.
  - **Global Audit (`query=None`):** Returns all active violations across the vault.
  - **Forced Re-Linting (`force=True`):** Bypasses the cache and executes a live `validate_wiki_graph_fast` or `validate_wiki_graph` pass, updating the `compiled_violations` table.

#### 4. Ontology Layer FTS & Vector Indexing Invariant
- For GraphRAG retrieval (`query_wiki`) to traverse both ground-truth note leaves and the compiled ontology graph, the ontology layer must be fully indexed:
  - Whenever dynamic ontologies are ingested (`ingest_ontology()`) or hypernyms are induced at compile time, their names and definitions **must be inserted into `query_fts` (FTS5)**, idempotently (re-ingestion replaces rows).
  - External ontology classes additionally get one space-S vector in **`entity_vec`** (partition = ontology prefix), making them Tier 2 identity candidates for note mentions. They are never written to `leaf_nodes` ([`ADR-012`](ADR-012.md) §5).
  - This guarantees that `compute_seed_candidates()` can seed random walks from ontology classes (via FTS5, and via hard merges or `closeMatch` edges from note mentions) as well as raw note chunks. There is no query → node vector seeding ([`ADR-012`](ADR-012.md) §4).
  - `vault/wiki/{namespace}/{slug}.md` remains a deterministic read-only Markdown/Turtle projection for human navigation; it is never re-indexed as raw input by CocoIndex, strictly preserving **Invariant 1 (Unidirectional Substrate Mutation)**.

---

### Consequences & Trade-Offs

#### Positive
- **Instantaneous Linter Response:** `lint_wiki` responds in $<5\text{ ms}$ over FastMCP instead of stalling client sessions for multi-second graph validations.
- **Protected Continuous Ingestion:** Streaming raw note chunking in CocoIndex remains sub-second, completely decoupled from expensive SHACL validation.
- **Deterministic Epistemic Feedback:** Contradictions and shape violations become first-class, inspectable entities in SQLite, enabling longitudinal tracking of vault quality.
- **Seamless GraphRAG Seeding:** Seeding can discover both note chunks and ontology concepts via the unified FTS5 index, and ontology classes become reachable from note mentions through `entity_vec` Tier 2 candidates.

#### Negative & Mitigations
- **Compilation Latency:** `compile_wiki()` incurs an additional $<200\text{ ms}$ validation step. Mitigated by using relational pre-closure (`validate_wiki_graph_fast`) without heavy DL inference.
- **Eventual Consistency of Lint Cache:** If notes are modified but `compile_wiki()` has not yet run, `lint_wiki()` reflects the state as of the last compilation. Mitigated by providing `force=True` on `lint_wiki()` for immediate on-demand re-validation, and triggering compilation automatically on debounced batch ingestion.
