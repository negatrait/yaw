# ADR 013: Open discovery, declarative semantics and revisable interpretation

**Status:** Accepted direction, amended by [ADR-014](ADR-014.md), 2026-10-12; implementation pending Epic 7.8\
**Authority:** User-directed reconciliation of the [review](../reviews/open-ie-ontology-review-2026-10-12.md)\
**Governing contract:** [FOUNDATIONAL](../../FOUNDATIONAL.md)\
**Implementation:** [Epic 7.8](../epic7.8-open-ie-ontology-alignment.md)

## Context

The review found domain semantics split across ontology resources, Python tables and SQL; contradictory extraction recipes; lossy source grounding; unsafe identity assumptions; and semantic-kind, cache and verification gaps. Some executable defects follow the old specifications faithfully, so code-only repairs would reproduce the drift.

## Decision

Adopt the reconciled FOUNDATION contract: open extraction preserves source assertions; semantic resources define domain interpretation; generic code executes that interpretation; learned knowledge remains traceable; ambiguous identity is preserved; derived projections are revisable and versioned.

The existing single-stage CocoIndex, single SQLite, spaCy/spacy-llm, SciPy, FastMCP and optional Markdown output remain. One extraction request per changed bounded unit implements the qualified payload; ADR-014 also selects scheduled comparison and synthesis stages through the same adapter. Importing an ontology must not silently narrow discovery. ADR-014 and the compiler guide settle the single implementation, failure behavior and pre-Epic-8 gate.

A fixed vocabulary moved into Turtle is still a closed discovery system if every extraction must fit it. Built-in and external profiles guide alignment and scoped views while unfamiliar relations remain representable.

## Evidence and trade-offs

[EDC](https://aclanthology.org/2024.emnlp-main.548/) motivates separating extraction, definition and canonicalization responsibilities, not YAW's former heuristic merge rules. [MinIE](https://aclanthology.org/D17-1278/) motivates preserving factual qualifiers. [HippoRAG 2](https://arxiv.org/html/2502.14802v2) motivates testing query-to-fact retrieval; its results do not certify YAW.

The trade-off is more explicit occurrence, assertion and interpretation metadata and selective recomputation. It avoids source loss and lets ontology resources change without silently redefining past evidence. Similarity alone can yield useful retrieval associations while remaining insufficient for identity.

## Verification and migration

Acceptance is an architectural decision authorized by the user's reconciliation request, not a claim of empirical completion. Epic 7.8 must prove the unfamiliar-property vertical slice, qualifier/direction preservation, source revision checks, cache identity, kind-aware projection, scoped validation and independent evaluation.

Re-extract source records whose surfaces were already overwritten, review old heuristic aliases and rebuild dependent projections. No documentation change repairs existing databases. Follow the persisted epic checklist and readiness evidence before closing implementation work.
