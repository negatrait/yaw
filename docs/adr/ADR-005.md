# ADR 005: 9-Root Universal Hierarchy & Dynamic View Namespace Inheritance

**Status:** Accepted\
**Date:** 2026-10-05\
**Amended by:** [ADR-012](ADR-012.md) — `aliases.status` is retired (aliases are hard identity only); `close_matches` projects to `skos:closeMatch` / `yaw:closeMatch`; `canon_verdicts` is not projected (no `owl:differentFrom`).\
**Governing Canon:** [`FOUNDATIONAL.md §5.1, §5.2`](../../FOUNDATIONAL.md), [`docs/ontological-roots.md`](../ontological-roots.md)\
**Implementation:** [`src/yaw/config.py`](../../src/yaw/config.py), [`src/yaw/storage/db.py`](../../src/yaw/storage/db.py), [`src/yaw/nlp/extractor.py`](../../src/yaw/nlp/extractor.py)

---

### Context & Problem Statement

Unconstrained LLM knowledge extraction generates volatile, ad-hoc taxonomic types across different document chunks (e.g. inventing `"theorems"`, `"notions"`, `"ideas"` instead of standardizing on `"concepts"`). Left unconstrained:
1. **Ontological Entropy:** Top-level categories multiply indefinitely, preventing coherent graph partitioning and hierarchical aggregation.
2. **Table Churn on Canonicalization:** When an extracted entity mention (e.g., `entities:einstein`) is canonicalized to a primary node (e.g., `concepts:albert-einstein`), destructive updates to underlying relational tables (`leaf_nodes`, `leaf_relations`) create high lock contention and risk data corruption.

### Decision

1. **Establish the 9-Root Universal Hierarchy:**
   Enforce a closed set of 9 top-level ontological universal namespaces ([`config.TAXONOMY_NAMESPACES`](../../src/yaw/config.py)):
   - `entities`: Concrete named individuals, organizations, locations, artifacts.
   - `concepts`: Abstract ideas, theories, mathematical formulations, domain paradigms.
   - `predicates`: Structural, causal, and comparative relations.
   - `invariants`: Formal mathematical laws, system constraints, non-negotiable rules.
   - `decisions`: Architectural trade-offs, design choices, rationale artifacts.
   - `claims`: Hypotheses, assertions, dialectical conjectures.
   - `processes`: Algorithms, workflows, lifecycles, execution procedures.
   - `sources`: Citations, bibliographic origins, external URLs, reference documents.
   - `contexts`: Domain boundaries, execution environments, temporal frames.

2. **Implement Dynamic View Namespace Inheritance:**
   All canonical resolution and namespace inheritance is handled non-destructively through SQLite relational views (`unified_nodes` and `unified_edges` in [`src/yaw/storage/db.py`](../../src/yaw/storage/db.py)):
   ```sql
   CREATE VIEW unified_nodes AS
   SELECT
       entity_uri AS node_id,
       heading AS name,
       'chunk' AS namespace,
       rel_path AS definition
   FROM note_chunks
   UNION ALL
   SELECT DISTINCT
       COALESCE(a.canonical_id, ln.node_id) AS node_id,
       ln.name,
       CASE
           WHEN a.canonical_id IS NOT NULL AND instr(a.canonical_id, ':') > 0
           THEN substr(a.canonical_id, 1, instr(a.canonical_id, ':') - 1)
           ELSE ln.namespace
       END AS namespace,
       ln.definition
   FROM leaf_nodes ln
   LEFT JOIN aliases a
       ON a.alias_id = ln.node_id
       AND a.kind = 'entity';
   ```
   - When an alias is recorded, `unified_nodes` dynamically strips and re-attributes the namespace prefix from `canonical_id`.
   - `unified_edges` performs a 3-way `LEFT JOIN` on `aliases` for `src_id`, `dst_id`, and `rel_type`.

3. **Map 9-Root Universals to W3C SKOS & OWL 2 RL Standards:**
   To guarantee interoperability with semantic web tooling without operational daemon overhead, the 9 universal root classes and dynamic view entities map directly to standard W3C SKOS and OWL 2 RL axioms:

   | YAW Concept / Field | W3C Standard Representation | Semantic Role & Mapping Contract |
   | :--- | :--- | :--- |
   | **Canonical Node** (`node_id`) | `skos:Concept`, `owl:Class` | `<https://yaw.local/concept/{slug}>` typed instance of its root class universal. |
   | **Canonical Label** (`ln.name`) | `skos:prefLabel`, `rdfs:label` | Authoritative surface form for the concept (`"Transformer Architecture"@en`). |
   | **Alias** (`alias_id`, hard identity) | `skos:altLabel`, `owl:sameAs` | Variant surface strings and synonyms (`"Attention Model"@en`). `aliases` rows project as `owl:sameAs` equivalence via view joins. |
   | **Taxonomic Edges** (`manifests_in`, splits) | `rdfs:subClassOf`, `skos:broader` / `skos:narrower` | Hierarchical hypernym induction ([`ADR-002`](ADR-002.md)) conforms to transitive `rdfs:subClassOf` and `skos:broader`. |
   | **Soft Identity** (`close_matches`) | `skos:closeMatch` (vault ↔ external ontology), `yaw:closeMatch` (intra-vault) | Symmetric, non-transitive candidate links ([`ADR-012`](ADR-012.md) §5). `canon_verdicts` is **not** projected: a `distinct` verdict means "not merged", not evidence of non-identity, so `owl:differentFrom` would be unsound under the open-world assumption. |
   | **Source Chunk Grounding** | `prov:wasDerivedFrom`, `prov:Entity` | Links extracted nodes to byte-level chunk citations (`yaw:sources/{rel_path}#chunk:{id}`). |

   **The 9 Root Universals as OWL 2 RL Classes:**
   Each root universal is formalized as an `owl:Class` (subclass of `skos:Concept` or `owl:Thing`):
   - `yaw:Entity` (`rdfs:subClassOf owl:Thing`): Concrete individuals, institutions, artifacts.
   - `yaw:Concept` (`rdfs:subClassOf owl:Thing`): Abstract theoretical constructs and paradigms.
   - `yaw:Predicate` (`rdfs:subClassOf rdf:Property`): Relational properties and open IE verbs.
   - `yaw:Invariant` (`rdfs:subClassOf owl:Class`): Universal physical/computational constraints.
   - `yaw:Decision` (`rdfs:subClassOf owl:Class`): Architectural design choices and rationales.
   - `yaw:Claim` (`rdfs:subClassOf owl:Class`): Dialectical assertions, conjectures, hypotheses.
   - `yaw:Process` (`rdfs:subClassOf owl:Class`): Workflows, state transitions, algorithms.
   - `yaw:Source` (`rdfs:subClassOf prov:Entity`): Bibliographic citations, raw documents.
   - `yaw:Context` (`rdfs:subClassOf owl:Class`): Temporal, environmental, or domain scopes.

   **Pragmatic Profile Invariant:**
   Reasoning over these roots is strictly confined to the **OWL 2 RL** profile implemented via relational SQL (recursive CTEs, view joins) and SciPy CSR matrix operations. Heavy OWL 2 DL reasoners (tableaux solvers requiring Open World Assumption) are explicitly rejected.

### Consequences & Trade-offs

- **Positive:** Zero modification to immutable raw extraction records (`leaf_nodes`, `leaf_relations`, `note_chunks`).
- **Positive:** Canonicalization is instantaneous and reversible: adding or removing an `aliases` row immediately updates all views globally.
- **Positive:** Guarantees ontological convergence to the 9 roots across diverse unstructured notes.
- **Positive:** Full standard interoperability with W3C SPARQL endpoints, SKOS taxonomy tools, and RDF serializers (`rdflib`) without needing dedicated graph database daemons.
- **Positive:** Clear mapping between relational SQLite columns/views and W3C SKOS (`prefLabel`/`altLabel`/`closeMatch`) / OWL 2 RL (`sameAs`/`subClassOf`).
- **Trade-off:** SQL queries over `unified_nodes` and `unified_edges` require evaluating `LEFT JOIN` expressions, mitigated by covering indexes (`idx_aliases_canonical`, `idx_aliases_lookup`).
