# ADR 008: W3C Semantic Alignment (SKOS/OWL/PROV-O Mappings, RDF Quad View Projections, and Seeded Predicates)

**Status:** Accepted\
**Date:** 2026-10-06\
**Amended by:** [ADR-012](ADR-012.md) — `canon_verdicts` is no longer projected to `owl:differentFrom`; `close_matches` projects to `skos:closeMatch` / `yaw:closeMatch`; `contested` merges are replaced by the ambiguous-identity `sh:Warning`.\

### Context & Problem Statement

YAW extracts structured knowledge across 9 root namespaces (`concepts`, `entities`, `predicates`, `claims`, `invariants`, `decisions`, `processes`, `sources`, `contexts`) directly from plain Obsidian Markdown notes.

This architectural requirement presents a core tension:
1. **Zero Note-Taker Burden:** Obsidian note-takers author plain Markdown, bulleted thoughts, and natural `[[wikilinks]]`. They must never be burdened with RDF syntax, Turtle prefixes, JSON-LD boilerplate, or XML schema definitions.
2. **Open IE Predicate Proliferation:** Unconstrained Open Information Extraction (Open IE) prompts generate sprawling, uncontrolled synonyms for identical semantic relations (e.g., `is_subclass_of`, `child_of`, `kind_of`, `subClassOf`, `is_a`, `derives_from`, `derivedFrom`), exploding graph entropy and increasing LLM arbitration overhead during retrieval.
3. **Formal Semantic Web Interoperability:** Downstream enterprise consumers, SPARQL query endpoints, graph reasoning systems, and SHACL linters require strict compliance with authoritative W3C standards (SKOS, OWL 2 RL, PROV-O, SHACL, and SPARQL 1.1 Service Description).
4. **Lossless Byte-Level Provenance:** Triples in extraction must preserve their source chunk origin and contextual named graph without requiring an external graph database daemon.

### Decision

Align YAW's relational substrate, dynamic views, and extraction steering with formal W3C Semantic Web standards through four coordinated mechanisms:

#### 1. Root Namespace 1:1 W3C Semantic Type Bindings
Every extracted node belongs to one of 9 canonical root namespaces. Each namespace binds deterministically to standard W3C semantic classes:

| Root Namespace | Primary W3C Semantic Class | Secondary / Alignment Type | Semantic Role & Mapping Contract |
| :--- | :--- | :--- | :--- |

| `entities:*` | `owl:NamedIndividual` (`http://www.w3.org/2002/07/owl#NamedIndividual`) | `schema:Thing` | Concrete named individuals, organizations, software artifacts, hardware. |

#### 2. RDF Quad Projection in SQLite Views
Rather than maintaining an external triple store daemon, YAW projects SQLite relational tables directly into W3C RDF Triples and Named Quads via relational views:

- **`unified_edges` Quad Projection:**
  The `unified_edges` view aliases relational foreign keys into standard Quad components:
  - `src_id` $\rightarrow$ `subject` (`yaw:<src_namespace>:<src_slug>`)
  - `rel_type` $\rightarrow$ `predicate` (`yaw:predicates:<normalized_pred>`)
  - `dst_id` $\rightarrow$ `object` (`yaw:<dst_namespace>:<dst_slug>`)
  - `source_chunk_id` $\rightarrow$ `graph_uri` (`yaw:sources/{rel_path}#chunk:{chunk_id}`)

- **`unified_nodes` SKOS / OWL Projection:**
  - `node_id` $\rightarrow$ RDF URI (`<https://yaw.local/{namespace}/{slug}>` or CURIE `yaw:{namespace}:{slug}`)
  - `name` $\rightarrow$ `skos:prefLabel` and `rdfs:label`
  - `namespace` $\rightarrow$ `rdf:type` (via the 1:1 root mapping table)
  - `definition` $\rightarrow$ `skos:definition`

- **`aliases`, `close_matches` and Identity Resolution ([`ADR-012`](ADR-012.md) §5):**
  - `alias_id` $\rightarrow$ `skos:altLabel` (lexical synonym variant)
  - Hard canonical merges (`aliases` rows) $\rightarrow$ `owl:sameAs`
  - Soft identity (`close_matches`) $\rightarrow$ `skos:closeMatch` across concept schemes (vault ↔ external ontology) and `yaw:closeMatch` within the vault (`owl:SymmetricProperty`, not transitive, not a sub-property of `skos:closeMatch`)
  - `canon_verdicts` is **not** projected: a `distinct` verdict means "not merged", not evidence of non-identity, so `owl:differentFrom` would be unsound under the open-world assumption and would conflict with any later `owl:sameAs` via OWL 2 RL rule `eq-diff1`

- **Compiled Subsumption Knowledge:**
  - Hypernym nodes induced during saturated hub splits ([`ADR-002`](ADR-002.md)) project into `unified_nodes` via `compiled_nodes`.
  - Rewired `subClassOf` edges project into `unified_edges` via `compiled_relations` with `source_chunk_id = 'compiled:' || relation_id`, preserving raw extraction substrate purity (Invariant 1).

#### 3. Categorized Extraction Predicate Seeding
To halt synonym explosion during spaCy-LLM extraction, YAW establishes an authoritative seed vocabulary partitioned across four fundamental semantic categories in `config.BASE_PREDICATES`:

1. **Subsumption & Mereology:**
   - `subClassOf`: Hierarchical ontological specialization ($A \sqsubseteq B$, transitive).
   - `partOf`: Mereological component containment ($A \prec B$).
   - `instanceOf`: Instantiation of a class by an individual ($a \in C$).
2. **Dialectical & Argumentation:**
   - `supports`: Evidential or theoretical corroboration ($A \vdash B$).
   - `refutes`: Empirical or logical negation of a claim ($A \nvdash B$).
   - `contradicts`: Mutually exclusive assertions ($A \land B \bot$).
   - `supersedes`: Temporal or architectural replacement ($A \succ_{t} B$).
3. **Dependency & Process:**
   - `dependsOn`: Structural, runtime, or conceptual prerequisite.
   - `causes`: Causal transformation or state outcome.
   - `precedes`: Temporal ordering in workflow execution.
   - `produces`: Activity outcome generating an entity or artifact.
4. **Provenance & Grounding:**
   - `derivedFrom`: Traceable lineage to prior entity or source chunk (`prov:wasDerivedFrom`).
   - `cites`: Explicit bibliographic or textual attribution.
   - `manifestsIn`: Realization of an abstract concept in a concrete artifact or observation.

##### Predicate Axioms & Characteristics Specification
To ensure deterministic graph traversal, correct transitive closure during GraphRAG retrieval, and automated conflict detection in `lint_wiki`, the 10 canonical seed predicates carry formal OWL 2 property characteristics:

| Seed Predicate | Primary OWL 2 Type | RDFS / W3C Super-Property | Property Characteristics & Axioms | Formal Semantic Contract |
| :--- | :--- | :--- | :--- | :--- |
| `predicates:subClassOf` | `owl:TransitiveProperty` | `rdfs:subPropertyOf rdfs:subClassOf` | `rdfs:subPropertyOf predicates:Root` | Ontological specialization ($A \sqsubseteq B$). Transitive: $A \sqsubseteq B \land B \sqsubseteq C \implies A \sqsubseteq C$. |
| `predicates:partOf` | `owl:TransitiveProperty` | — | `rdfs:subPropertyOf predicates:Root` | Mereological component containment ($A \prec B$). Transitive: $A \prec B \land B \prec C \implies A \prec C$. |
| `predicates:instanceOf` | `owl:ObjectProperty` | `rdfs:subPropertyOf rdf:type` | `rdfs:subPropertyOf predicates:Root` | Class instantiation ($a \in C$). Relates a concrete individual or entity to its governing concept class. |
| `predicates:supports` | `owl:ObjectProperty` | — | `owl:propertyDisjointWith predicates:refutes`<br>`owl:propertyDisjointWith predicates:contradicts` | Dialectical corroboration ($A \vdash B$). Evidence, rationale, or proof supporting a proposition. |
| `predicates:refutes` | `owl:ObjectProperty` | — | `owl:propertyDisjointWith predicates:supports` | Dialectical negation or empirical counter-evidence ($A \nvdash B$). Asymmetric refutation of a claim. |
| `predicates:contradicts` | `owl:ObjectProperty`<br>`owl:SymmetricProperty` | — | `owl:propertyDisjointWith predicates:supports` | Mutual logical exclusivity ($A \land B \bot$). Symmetric: $A \text{ contradicts } B \iff B \text{ contradicts } A$. |
| `predicates:supersedes` | `owl:TransitiveProperty`<br>`owl:AsymmetricProperty` | — | `rdfs:subPropertyOf predicates:Root` | Temporal or architectural replacement ($A \succ_{t} B$). Irreflexive & asymmetric evolution. |
| `predicates:dependsOn` | `owl:TransitiveProperty` | — | `rdfs:subPropertyOf predicates:Root` | Structural, computational, or execution dependency ($A \to B$). Transitive dependency propagation. |
| `predicates:derivedFrom` | `owl:ObjectProperty` | `rdfs:subPropertyOf prov:wasDerivedFrom` | `rdfs:subPropertyOf predicates:Root` | Lineage and provenance grounding. Connects extracted knowledge directly to source chunks or prior artifacts. |
| `predicates:manifestsIn` | `owl:ObjectProperty` | — | `rdfs:subPropertyOf predicates:Root` | Realization / embodiment. Relates abstract concept or invariant to concrete entity, codebase, or observation. |

**Few-Shot Prompt Steering:**
The spaCy-LLM extraction prompt dynamic steering mechanism (`@registry.misc("yaw.CanonicalExamples.v1")`) injects these canonical predicates together with top-conductance predicates from `unified_edges`. This bounds LLM generation to the canonical vocabulary, falling back to open IE predicates only when source text expresses a genuinely novel relation.

#### 4. SHACL Shapes as Wiki Lint Contracts
Closed-world data quality is validated via W3C SHACL (Shapes Constraint Language) in `lint_wiki`:
- Shape constraints enforce maximum definition length ($\le 50$ words), canonical URI syntax compliance, valid domain/range type assignments, and isolation of orphan nodes.
- Dialectical contradictions (e.g. concurrent `supports` and `contradicts` without qualifying context) trigger W3C `sh:ValidationReport` violations directly from SQLite view queries. Ambiguous identity (a node with $\ge 2$ `close_matches` targets that are not linked to each other) is reported as `sh:Warning` ([`ADR-012`](ADR-012.md); this replaces the retired `contested` merge state).
- Runs entirely in-process via `pyshacl` / `rdflib` with zero background server processes.

### Consequences & Trade-offs

#### Positive
- **Zero Note-Taker Cognitive Load:** Writers use native Markdown links (`[[quantum-entanglement]]`); the system maps them into standard W3C OWL/SKOS entities and quad graphs under the hood.
- **Controlled Predicate Cardinality:** Dynamic few-shot steering against `config.BASE_PREDICATES` prevents synonym proliferation, shrinking GraphRAG adjacency matrix sparsity and lowering LLM disambiguation cost.
- **Lossless In-Process Export:** Relational views project directly to Turtle, JSON-LD, N-Triples, and N-Quads via `rdflib.ConjunctiveGraph` without external triplestore overhead.
- **Standards-Compliant Linting:** Closed-world SHACL validations detect graph anomalies and dialectical conflicts deterministically.

#### Negative & Mitigations
- **Namespace Rigidity:** Extracted nodes must map cleanly into one of the 9 roots.
  *Mitigation:* The 9-root universal taxonomy ([`ADR-005`](ADR-005.md)) covers all operational domains; unclassified terms default gracefully to `concepts:*` (`skos:Concept`).
- **Prompt Token Overhead:** Ingesting seed predicates into LLM prompts consumes prompt tokens.
  *Mitigation:* `config.CANON_FEWSHOT_MAX` caps few-shot injection to $\le 5$ examples ($\le 250$ tokens), prioritizing top-conductance predicates.
