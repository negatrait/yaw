### Context & Problem Statement

Initial architectural iterations explored a dual-stage extraction pipeline coupling `spacy.SpanCat.v3` (for grammatical and entity role spans) into `spacy.REL.v1` (for pairwise relation assignment). In addition, early prototypes relied on procedural regex parsers to strip markdown code blocks and stream candidate JSON objects, alongside brute-force character iteration loops to reconcile span byte offsets against raw document text.

Empirical testing and deep source audits surfaced critical flaws in this approach:
1. **Upstream Label Drop Risk:** In `spacy_llm/tasks/span/parser.py`, `SpanCat.v3` strictly enforces `norm_label in task._label_dict`. Any emergent or nuanced epistemological category emitted by the LLM outside a fixed dictionary was silently discarded, degrading graph density.
2. **Dual-Stage Latency & Redundant Inference:** Chaining `SpanCat.v3` $\to$ `REL.v1` required two sequential LLM inference roundtrips per note chunk, doubling token consumption and wall-clock ingestion latency.
3. **Bridge Fragility & Complex Reconciler Glue:** Bridging `doc.spans["sc"]` into `doc.ents` and aligning index pairs for `REL.v1` introduced brittle glue code prone to indexing misalignments.
4. **Fragile Regex Streaming & Brute-Force Character Alignment:** Over 150 lines of bespoke regex heuristics, markdown fence stripping loops, and character-by-character search algorithms created maintenance debt and unpredictable parsing failures on non-standard LLM completions.

### Decision

1. **Single Unified Extraction Pipeline via `spacy.Raw.v1`:**
   - Eliminate competing parallel extraction pipelines and deprecate dual `SpanCat.v3` + `REL.v1` architectures.
   - Standardize on a single, unified `spacy.Raw.v1` pipeline configured with `OPEN_IE_RAW_TRIPLES_TEMPLATE` (`src/yaw/nlp/templates.py`).
   - The LLM extracts direct schema-free RDF/OWL/SKOS Open IE triples in a single pass:
     ```json
     {"subject": "<entity>", "predicate": "<relation_phrase>", "object": "<entity>"}
     ```
2. **Native Disk Caching via `spacy.BatchCache.v1`:**
   - Mount `spacy.BatchCache.v1` directly into the `llm` pipeline within `build_leaf_pipeline()`:
     ```python
     cache_cfg = {
         "@llm_misc": "spacy.BatchCache.v1",
         "path": str(Path(cache_dir or config.SPACY_CACHE_DIR)),  # ".cache/spacy_llm"
         "batch_size": 1,
         "max_batches_in_mem": 4,
     }
     ```
   - Guarantees deterministic, automatic disk caching of LLM prompt-response pairs, ensuring zero redundant network or GPU inference requests for identical note contents.
3. **Robust Payload Deserialization via `extract_json_payload()`:**
   - Remove fragile regex streaming parsers and markdown fence stripping loops.
   - Utilize standard library `json.loads` and `json.JSONDecoder.raw_decode` in `extract_json_payload()` to systematically resolve outer bracketed arrays `[...]`, single objects `{...}`, or streaming JSON lines without procedural heuristics.
4. **Clean Span Alignment via `align_span()`:**
   - Remove brute-force character search loops.
   - Align extracted surface spans directly against unmutated `doc.text` using `doc.char_span(start, end, alignment_mode="contract")` followed by `alignment_mode="expand"`.
   - Filter span overlaps cleanly via `spacy.util.filter_spans()`, guaranteeing exact byte provenance (Invariant E1) with zero token distortion.
5. **Decoupled Downstream Grounding:**
   - Downstream ontological categorization is cleanly handled via `spacy.TextCat.v3` (with `yaw.LabelNormalizer.v1`), and canonicalization is delegated exclusively to the Two-Tier Convergence Engine (`yaw.indexer.canonicalize`).

### Consequences & Trade-offs

- **Positive:** Latency and token consumption per chunk reduced by ~50% (one LLM inference call per chunk instead of two).
- **Positive:** Completely schema-free: emergent predicates and open epistemological categories are extracted without upstream dictionary truncation.
- **Positive:** Automatic disk caching via `spacy.BatchCache.v1` accelerates test execution and re-indexing runs to near-zero latency for cached corpora.
- **Positive:** Eliminates 150+ lines of brittle regex parsing and character search loops in favor of robust standard library deserialization.
- **Trade-off:** Requires robust downstream predicate normalization and entity canonicalization to handle lexical entropy from schema-free extraction (addressed in ADR-003 and ADR-006).
