# ADR 009: Pluggable Ontology Substrates, Lossless Ingestion Matrix, and Non-Punning Dual-Epistemic Architecture

**Status:** Accepted\
**Date:** 2026-10-09\
**Governing Canon:** [`FOUNDATIONAL.md §1–§5`](../../FOUNDATIONAL.md), [`docs/ADR.md`](../ADR.md), [`docs/adr/ADR-002.md`](ADR-002.md), [`docs/adr/ADR-005.md`](ADR-005.md), [`docs/adr/ADR-008.md`](ADR-008.md)\
**Implementation:** `src/yaw/ontology/`, `src/yaw/storage/`, `src/yaw/nlp/`, `src/yaw/retrieval/`, `src/yaw/server/`

---

### Context & Problem Statement

YAW was originally designed with an internal, hardcoded ontology namespace structure (`src/yaw/ontology.ttl`, ADR-005, ADR-008) and 14 canonical predicates. While this provided clean out-of-the-box bootstrapping for general Obsidian vaults, specialized domain deployments (e.g., civil engineering with DiCo/BFO, biomedical with MeSH, provenance tracking with PROV-O, enterprise taxonomies with SKOS) require:
1. **Pluggable Domain Models:** Ingesting arbitrary external W3C RDF/OWL ontologies or SKOS Concept Schemes without modifying engine code.
2. **Configurable Open-IE Extraction:** Supporting strict closed-domain extraction alongside open-ended dialectical knowledge extraction across a 2x2 matrix (`target: internal|external` × `open_ie: true|false`).
3. **The Lossless Ingestion Constraint (Invariant 2):** Switching between ontologies or toggling `open_ie` must **never discard extracted leaf triples** or trigger catastrophic re-indexing / EmbeddingGemma cache wipes.
4. **Metamodeling Punning Elimination:** Historical drafts informally punned `owl:Class` and `skos:Concept` on identical URIs (`concepts:Root a owl:Class, skos:Concept`), violating strict W3C semantics and confusing reasoning engines.
5. **Conductance Inversion Remediation:** Naive depth-scaled conductance formulas inverted ADR-002 by increasing upward conductance towards 1.0 at root proximity ($\text{depth}=0$), diluting GraphRAG seed mass into generic roots.

---

### Decision

Implement the pluggable ontology subsystem, lossless multi-quadrant extraction matrix, and strict dual-epistemic W3C architecture through the following technical specifications:

#### 1. The 2x2 Operational Matrix & Zero Cache-Wipe Guarantee
The engine supports four runtime quadrants via `target_ontology: "internal" | "external"` and `open_ie: bool`:

```
                             TARGET ONTOLOGY
                     Internal                External
               +-----------------------+-----------------------+
        true   |      Quadrant 1       |      Quadrant 3       |
               |      Hybrid Open      |     Hybrid Domain     |
OPEN           |      IE + 9-Root      |     Open IE + Ext     |
IE?            +-----------------------+-----------------------+
        false  |      Quadrant 2       |      Quadrant 4       |
               |      Strict Fixed     |     Chunk-Scoped      |
               |     14 Predicates     |     Closed Domain     |
               +-----------------------+-----------------------+
```

| Quadrant | Target | Open IE? | Ingestion & Storage Semantics | Active Retrieval View (`unified_edges`) |
| :--- | :--- | :--- | :--- | :--- |
| **Q1** | `internal` | `true` | **Lossless**: Ingest leaf triples into `leaf_relations`; align to `src/yaw/ontology.ttl`. Fallback to open predicates under `predicates:{slug}`. | Includes all extracted and compiled relations (`open_ie_filter=0`). |
| **Q2** | `internal` | `false` | **Lossless**: Ingest leaf triples into `leaf_relations`. Out-of-vocabulary triples stored for audit provenance. | Filters edges where `rel_type NOT IN (SELECT canonical_id FROM aliases WHERE kind='predicate')` and not in `BASE_PREDICATES`. |
| **Q3** | `external` | `true` | **Lossless**: Ingest leaf triples; align to external OWL classes / SKOS concepts. Fallback open predicates retained under `wiki:predicates:{slug}`. | Includes external properties + normalized open predicates. |
| **Q4** | `external` | `false` | **Lossless**: Ingest leaf triples; mentions scoped via NER/Trie against `dynamic_classes`. Closed domain strictly according to external ontology. | Filters edges strictly to registered external ontology properties (`dynamic_properties`) and canonical predicates. |

**The Zero Cache-Wipe Invariant:** Toggling between quadrants is a zero-cost (< 5 ms), read-time SQL view toggle. Raw extractions in `leaf_relations` are immutable and lossless. CocoIndex content-hash caches and EmbeddingGemma chunk embeddings are never invalidated or recomputed on configuration changes.

#### 2. Dual-Epistemic Architecture: OWL 2 RL Schema vs SKOS Thesaurus (Non-Punning)
YAW recognizes OWL and SKOS as first-class, non-overlapping architectural peers:
- **OWL 2 RL / RDFS (Domain Schema):** Defines formal domain classifications (`owl:Class`), object properties (`owl:ObjectProperty`), class subsumption (`rdfs:subClassOf`), and property characteristics (`owl:TransitiveProperty`, `owl:propertyDisjointWith`).
- **SKOS (Vault Thesaurus):** Defines epistemic knowledge organization, controlled vocabularies, concept schemes (`skos:ConceptScheme`, `yaw:VaultScheme`), labels (`skos:prefLabel`, `skos:altLabel`), and thesaurus navigation (`skos:broader`, `skos:narrower`, `skos:related`).
- **The Non-Punning Invariant:** An entity URI is typed strictly as *either* an `owl:Class` or a `skos:Concept`, **never both simultaneously**. Punning (`concepts:Root a owl:Class, skos:Concept`) is an anti-pattern and strictly prohibited.
- **Zero Synthetic Wrappers:** Class subsumption is standard `rdfs:subClassOf`; synthetic wrappers (`predicates:subClassOf a owl:ObjectProperty`) are excised. Thesaurus hierarchy is strictly `skos:broader` and `skos:narrower`.

#### 3. Storage Schema & View Projection
External ontologies materialize in SQLite without external servers:
- **`dynamic_ontologies`:** Catalog of active external ontologies (`ontology_id`, `prefix`, `base_uri`, `format`, `loaded_at`).
- **`dynamic_classes`:** Hierarchy table storing classes/concepts (`curie`, `uri`, `ontology_id`, `label`, `parent_class_uri`, `depth`, `is_root`, `epistemic_type CHECK(epistemic_type IN ('class', 'concept'))`).
- **`dynamic_properties`:** Property axioms (`curie`, `uri`, `ontology_id`, `label`, `parent_property_uri`, `is_transitive`, `inverse_property_uri`).
- **`aliases` Materialization:** Ontology classes and labels populate `aliases` with `kind IN ('entity', 'predicate')` and `method = 'ontology'`. The `aliases.method` CHECK constraint is extended to accept `'ontology'`.
- **`unified_edges` Projection:** Includes a dedicated branch projecting `dynamic_classes` and `dynamic_properties` hierarchies into standard `rdfs:subClassOf`, `skos:broader`, and `rdfs:subPropertyOf` edges.
- **Index Seek Preservation:** Joins on `aliases` in `unified_edges` are strictly equality seeks on `a_pred.alias_id = lr.predicate_id` (pre-slugged at ingestion time), eliminating runtime `replace(lower(...))` calls inside SQL joins.

#### 4. Upward Conductance Damping Correction
To preserve Invariant 4 and ADR-002, upward taxonomic conductance must **damp towards 0.2 at root proximity**, preventing seed mass from escaping into generic root classes (`owl:Thing`, `concepts:Root`):
$$W_{\text{up}}(u, v) = \min\left(0.8, \max\left(0.2, 0.2 + 0.1 \times \text{depth}(v)\right)\right)$$
- When $v$ is a root class ($\text{depth} = 0$), $W_{\text{up}} = 0.20$ (maximum damping).
- When $v$ is deep ($\text{depth} \ge 6$), $W_{\text{up}} = 0.80$ (permissive local abstraction).
- Downward subsumption broadcast remains $W_{\text{down}} = 1.0$.

#### 5. Antonym-Guarded Predicate Normalization
Eliminates polarity collapse (`causes` $\approx$ `prevents`, `supports` $\approx$ `refutes`) without ungrounded GloVe vectors:
- **Tier 1 (Ontology & Alias Direct Match):** Checks `aliases` (`kind='predicate'`) and `dynamic_properties`.
- **Tier 2 (Canonical Synsets & Polarity Mask):** Lemmatizes candidate verbs and phrases (including multi-word phrases such as `"lead to"` or `"results in"`). Blocks merges across the explicit `POLARITY_EXCLUSION_MASK`.
- **Tier 3 (Open Verb Fallback):** Slugs and mints `wiki:predicates:{slug}` when `open_ie=true`.

> These are predicate-normalizer tiers (space L), distinct from the entity Two-Tier Identity Protocol: predicates never enter entity Tier 2 and trigger zero embedding calls. Per [`ADR-012`](ADR-012.md) §2, a polarity-guarded static-vector fallback onto the base predicates runs after the synset tier and before the open verb fallback.

#### 6. Relational Pre-Closure & Lean pySHACL (< 200 ms)
- Subsumption and subproperty closures are computed in-process via SQLite recursive CTEs (`WITH RECURSIVE`) and cached CSR matrix powers.
- `pyshacl.validate(data_graph, shacl_graph=wiki_shapes, inference=None)` executes over the relationally pre-closed graph in < 200 ms, avoiding Python heap bloat and GC pauses.
- Dynamic whitelist shapes target `sh:targetSubjectsOf rdf:type` to validate active namespace membership.

#### 7. FastMCP Server Contracts
Exposes declarative runtime ontology and extraction controls:
- `@mcp.tool() async def load_ontology(ontology_path: str, prefix: str | None = None, vault_dir: str | None = None) -> dict[str, Any]`
- `@mcp.tool() async def set_extraction_mode(open_ie: bool, target_ontology: str = "internal", vault_dir: str | None = None) -> dict[str, Any]`

---

### Consequences & Trade-offs

#### Positive
- **100% In-Process & Daemon-Free:** Zero external graph engines; all storage, closure, and validation run in SQLite and `pyshacl` in-process.
- **Zero-Loss Guarantees:** Switching between open and closed extraction modes is instant and non-destructive.
- **W3C Standards Compliance:** Strict non-punning separation of OWL and SKOS restores formal interoperability.
- **Root Mass Protection:** Corrected upward conductance prevents topic dilution in GraphRAG retrieval.

#### Negative / Mitigations
- **View Complexity:** Adding `dynamic_classes` to `unified_edges` introduces a 4th `UNION ALL` branch; mitigated by simple index seeks on `parent_class_uri IS NOT NULL`.
- **Schema Migration:** Existing vaults need an idempotent migration for `aliases.method` CHECK constraint; mitigated by automatic schema checking in `ensure_schema_tables()`.
