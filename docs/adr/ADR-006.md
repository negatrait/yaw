### Context & Problem Statement

Open Information Extraction (Open IE) triples extracted from natural language contain unbounded verbal, tense, and stylistic variations for identical relational predicates (e.g. `"accelerates"`, `"accelerated"`, `"is accelerating"`, `"causes"`, `"caused by"`, `"is_a"`, `"isA"`, `"is composed of"`, `"specialization of"`).
If left un-normalized:
1. **Edge Multiplexing & Conductance Dilution:** Un-normalized predicates create parallel divergent edges between identical nodes, diluting conductance and edge-type filtering during GraphRAG retrieval.
2. **Recursive Pipeline Re-entrancy & Defensive Hacks:** Prior prototypes invoked full pipeline passes `pipe(cleaned)` inside predicate normalizers, introducing recursion loops that required defensive monkeypatch guards (e.g., `if "llm_rel" not in nlp.pipe_names`) to prevent infinite recursion and duplicate LLM execution.
3. **LLM Cost & Latency Overhead:** Delegating verb canonicalization to external LLM calls introduces significant token overhead, latency spikes, and parsing unpredictability.

### Decision

Implement **Direct Non-Recursive Predicate Normalization** in [`normalize_predicate()`](file:///home/harri/yaw/src/yaw/nlp/extractor.py):

```
Raw Predicate String
         │
         ▼
┌─────────────────────────────────┐
│ 1. Direct Base & Alias Match    │──[Match in PREDICATE_ALIASES]──► Canonical Base Form
│    (17 Canonical Aliases)       │                                  (e.g. "partOf")
└─────────────────────────────────┘
         │ [No Direct Match]
         ▼
┌─────────────────────────────────┐
│ 2. Isolated Token Lemmatization │──[Match in PREDICATE_ALIASES]──► Canonical Base Form
│    (De-camelcase + Lemmatizer)  │
└─────────────────────────────────┘
         │ [No Match]
         ▼
┌─────────────────────────────────┐
│ 3. In-Process GloVe Similarity  │──[Cosine > 0.80]─────────────► Canonical Base Form
│    (nlp.vocab / doc.vector)     │
└─────────────────────────────────┘
         │ [Cosine <= 0.80 / No Match]
         ▼
Normalized Lemma or De-camelcased String
```

1. **Direct Fast-Path & Canonical Alias Dictionary (17 Aliases):**
   - Directly checks raw, lowercased, underscored, and spaced strings against `config.BASE_PREDICATES` and all 17 canonical entries in `PREDICATE_ALIASES`:
     - **`is_a` (7):** `"is_a"`, `"isa"`, `"is a"`, `"is an"`, `"are"`, `"type of"`, `"instance of"`
     - **`partOf` (5):** `"partof"`, `"part_of"`, `"part of"`, `"component of"`, `"subset of"`
     - **`subClassOf` (5):** `"subclassof"`, `"sub_class_of"`, `"subclass of"`, `"specialization of"`, `"subtype of"`
   - Resolves immediately to the canonical predicate with zero pipeline overhead.
2. **Isolated Token Lemmatization:**
   - De-camelcases strings (`re.sub(r"([a-z])([A-Z])", r"\1 \2", rel)`), strips underscores, and runs isolated token lemmatization via `_lemmatize_phrase()`.
   - Executes strictly isolated sub-components (`tok2vec`, `tagger`, `attribute_ruler`, `lemmatizer`) over `base_pipe.make_doc(text)`.
   - Checks the resulting lemma against the base predicate and alias dictionary.
3. **In-Process Static GloVe Vector Similarity (> 0.80):**
   - If direct lookup and lemmatization do not resolve to a base predicate, evaluates in-process vector cosine similarity via `_find_best_vector_match()`.
   - Utilizes static 300d vectors from `nlp.vocab` / `Doc.vector` / `Lexeme` (`en_core_web_lg`).
   - If cosine similarity against any candidate base predicate exceeds `CANON_SIM_THRESHOLD` (0.80), the base predicate is returned.
4. **Complete Elimination of Recursive Pipeline Calls & Defensive Guards:**
   - **Zero Recursive Execution:** `normalize_predicate()` never invokes `pipe(cleaned)` on the main LLM pipeline.
   - **Zero Defensive Guards:** The brittle defensive recursion check `if "llm_rel" not in nlp.pipe_names` is completely eliminated.
   - **Zero LLM Calls:** All predicate normalization is 100% deterministic, in-process, and CPU-bound.
5. **Substrate & View Integration:**
   - Normalized predicates are persisted to `leaf_relations.predicate`, and the `unified_edges` SQL view applies predicate alias resolution via `aliases(kind='predicate')`.

### Consequences & Trade-offs

- **Positive:** Microsecond execution speed: 100% in-process CPU execution with zero network or LLM token overhead.
- **Positive:** Prevents pipeline re-entrancy and eliminates defensive recursion guards.
- **Positive:** Standardizes inflected and multi-word predicates (e.g. `"is composed of"`, `"comprising"`, `"specialization of"`) to clean base forms.
- **Positive:** Deterministic, reproducible, and robust across all execution environments.
- **Trade-off:** Emergent domain-specific relational verbs not captured by base predicates or GloVe similarity default to clean lemmatized phrases, which are subsequent canonicalized via Tier 2 indexer views.
