### Context & Problem Statement

Extracted entity mentions and relation predicates exhibit high lexical entropy across independent markdown notes (e.g., "Albert Einstein", "A. Einstein", "Einstein", or "special-relativity" vs "Einsteinian relativity"). If left uncanonicalized, the knowledge graph fragments into disconnected synonym islands, defeating multi-hop Personalized PageRank (PPR) traversal and conductances.

Prior prototypes attempted a 3-tier resolver combining `difflib.SequenceMatcher` lexical fuzzy matching, `sqlite-vec` canopy scans, and an expensive Tier 3 LLM pairwise comparator (`_adjudicate_pair_with_llm` invoking Ollama `/api/chat`).
This historical design created severe architectural and performance bottlenecks:
1. **Prohibitive LLM Overhead:** Invoking an LLM pairwise comparator for borderline candidates introduces $\mathcal{O}(N \times M)$ latency, non-deterministic ingestion stalling, and token exhaustion.
2. **Procedural Code Smells:** $\mathcal{O}(N)$ procedural `difflib.SequenceMatcher` loops, unindexed BLOB scan ladders (`_scan_candidates_in_memory()`), and mutable verdict caches created CPU bottlenecks during re-indexing.
3. **Obsolete Enum Pollution:** Deprecated variants (`TIER_3_LLM`, `TIER_1_LEXICAL`, `FALLBACK_NEW`, `MatchMethod.LLM`, `MatchMethod.LEXICAL`, `MatchMethod.COMPILE`) leaked obsolete procedural and LLM execution states into type definitions.
4. **Premature Discretization:** Forcing every ambiguous surface form into a single greedy binary match dropped polysemous candidate hypotheses, corrupting graph canopy seeding.

### Decision

Deprecate the 3-tier procedural resolver and adopt the **Two-Tier Convergence Engine** backed by spaCy's native compiled C/Cython **`InMemoryLookupKB`** in [`src/yaw/indexer/canonicalize.py`](file:///home/harri/yaw/src/yaw/indexer/canonicalize.py):

```
Surface Form Mention (name, kind, namespace)
               │
               ▼
┌────────────────────────────────────────────────────────┐
│ Tier 1: Direct Match (Compiled C/Cython KB & SQLite)   │──[Match Found]──► Resolved Canonical Node
│ - Exact slug in leaf_nodes                             │                   (TierEnum.TIER_1_EXACT)
│ - Active alias in aliases                              │                   (MatchMethod.EXACT / ALIAS)
│ - leaf_relations / config.BASE_PREDICATES              │
│ - InMemoryLookupKB.get_alias_candidates(clean_name)    │
└────────────────────────────────────────────────────────┘
               │ [No Direct Match]
               ▼
┌────────────────────────────────────────────────────────┐
│ Tier 2: Near Match (Static In-Process Vectors)         │──[Cosine > 0.80]─► Consolidate into Canonical Node
│ - In-process 300d GloVe vectors from en_core_web_lg    │                   - _record_alias(method="auto")
│ - sqlite-vec cosine search (vec_distance_cosine)       │                   - (TierEnum.TIER_2_EMBEDDING)
│ - Candidate similarity > CANON_SIM_THRESHOLD (0.80)    │                   - (MatchMethod.AUTO)
└────────────────────────────────────────────────────────┘
               │ [Cosine <= 0.80 / No Match]
               ▼
┌────────────────────────────────────────────────────────┐
│ Fallback: Novel Canonical Induction                    │──► Create Canonical Node
│ - _create_canonical_node(namespace="concepts")         │    (TierEnum.NEW_INDUCTION)
│ - Register in leaf_nodes & InMemoryLookupKB            │    (MatchMethod.NEW, is_new=True)
└────────────────────────────────────────────────────────┘
```

1. **Native Cython `InMemoryLookupKB` Integration & Candidate Prior Distributions:**
   - Rather than ad-hoc python dictionaries or procedural string matching, candidate entity and alias lookup is powered by spaCy's native `InMemoryLookupKB`.
   - `InMemoryLookupKB` maintains an alias candidate distribution with prior probabilities $P(\text{entity } e \mid \text{alias } a) \in (0, 1]$ satisfying:
     $$\sum_{e \in \text{cands}(a)} P(e \mid a) = 1.0$$
   - Synchronized seamlessly from the database via `sync_kb_from_db(kb, conn)`:
     - Canonical nodes from `leaf_nodes` are registered with 300d unit vectors.
     - Base predicates and relation predicates are registered as canonical identities.
     - Active aliases from `aliases` are grouped by `alias_id`, normalized, and registered via `kb.add_alias(alias, entities, probabilities)`.
   - Microsecond alias evaluation: `kb.get_alias_candidates(alias)` returns compiled candidates directly in C/Cython without Python overhead.

2. **Purge of Obsolete Enum Variants & Verdict Records:**
   - All references to `CanonicalVerdict` and live pairwise adjudication tables during canonicalization are eliminated.
   - Enums are strictly pruned to canonical production states:
     ```python
     class TierEnum(str, Enum):
         TIER_1_EXACT = "tier_1_exact"
         TIER_2_EMBEDDING = "tier_2_embedding"
         NEW_INDUCTION = "new_induction"


     class MatchMethod(str, Enum):
         EXACT = "exact"
         ALIAS = "alias"
         AUTO = "auto"
         NEW = "new"
     ```
   - Obsolete variants (`TIER_3_LLM`, `TIER_1_LEXICAL`, `FALLBACK_NEW`, `MatchMethod.LLM`, `MatchMethod.LEXICAL`, `MatchMethod.COMPILE`) are completely removed from the engine.

3. **Tier 1: Direct Match (Zero Cost):**
   - **Knowledge Base Lookup:** Checks candidates in `InMemoryLookupKB` via `_lookup_kb(name, kb)`. If candidate exists, resolves immediately as `TierEnum.TIER_1_EXACT` with `MatchMethod.EXACT` or `MatchMethod.ALIAS`.
   - **Exact Slug & Active Alias:** Inspects `aliases` table for active mappings (`status = 'active'`) matching `surface_id`, `slug`, or raw `name`.
   - **Direct Entity / Predicate Tables:** Checks exact node slug matches in `leaf_nodes`, or direct base predicate matches in `config.BASE_PREDICATES` and `leaf_relations`.
   - Resolves immediately as `TierEnum.TIER_1_EXACT` with `score=1.0`.

4. **Tier 2: Near Match via In-Process Vector Proximity:**
   - Evaluates vector embeddings or static 300d GloVe vectors (`en_core_web_lg`) using `_get_or_compute_vector()`.
   - Queries `sqlite-vec` index (`vec_distance_cosine`) or in-process candidate vectors via `nlp.vocab` / `Doc.vector`.
   - If candidate cosine similarity exceeds `CANON_SIM_THRESHOLD` (default 0.80), the mention is consolidated into the existing canonical node via `_record_alias(conn, alias_id=surface_id, canonical_id=best_cand_id, method="auto", score=best_cosine, kb=kb)`.
   - Resolves as `TierEnum.TIER_2_EMBEDDING` with `method="auto"`, `is_new=False`.

5. **Fallback: Novel Canonical Node Creation:**
   - Mentions failing both Tier 1 and Tier 2 create a new canonical identity via `_create_canonical_node()` persisting to `leaf_nodes` when a `source_leaf_id` is present.
   - Registers the novel canonical entity into `InMemoryLookupKB` with its GloVe vector.
   - Resolves as `TierEnum.NEW_INDUCTION` with `method="new"`, `is_new=True`.

6. **Complete Elimination of Tier 3 LLM Pairwise Adjudication:**
   - Eliminate all live LLM pairwise adjudication during canonicalization (0 LLM calls during entity or predicate canonicalization).
   - Delete dead procedural code: remove `_scan_candidates_in_memory()` and $\mathcal{O}(N)$ `difflib.SequenceMatcher` loops.

7. **Decoupled View Rewiring:**
   - Canonical relationships and aliases are stored cleanly in the `aliases` table (`alias_id`, `kind`, `canonical_id`, `method`, `score`, `status`, `source_leaf_id`).
   - The `score` column records the candidate prior probability $P(\text{canonical\_id} \mid \text{alias\_id})$, feeding directly into GraphRAG PPR seeding and topological disambiguation ([`docs/adr/ADR-010.md`](file:///home/harri/yaw/docs/adr/ADR-010.md)).
   - Dynamic SQLite views (`unified_nodes`, `unified_edges`) route node and edge endpoints directly to `canonical_id` without destructive mutations to raw chunk or leaf records.

### Consequences & Trade-offs

- **Positive:** Zero LLM calls during entity or predicate canonicalization, eliminating network roundtrips, token costs, and timeout risks during continuous indexing.
- **Positive:** In-process compiled C/Cython candidate generation through `InMemoryLookupKB` achieves microsecond lookup speeds.
- **Positive:** Native preservation of alias candidate distributions $P(e \mid a) \in (0, 1]$ prevents premature winner-take-all discretization, laying the mathematical foundation for topological disambiguation in GraphRAG ([`docs/adr/ADR-010.md`](file:///home/harri/yaw/docs/adr/ADR-010.md)).
- **Positive:** Type-safe, purged enums: `TierEnum` and `MatchMethod` strictly reflect reality without obsolete dead variants.
- **Positive:** 100% deterministic and reproducible resolution backed by static GloVe vectors and exact alias graphs.
- **Trade-off:** High-entropy acronyms or non-distributional analogies with vector similarity $\le 0.80$ will mint separate canonical nodes until explicitly linked.
