# ADR 003: Two-Tier Convergence Engine for Entity & Predicate Canonicalization

**Status:** Accepted (Remediated Architecture)\
**Date:** 2026-10-05 (Updated 2026-10-11)\
**Amended by:** [ADR-012](ADR-012.md) — Tier 2 is no longer a vector auto-merge: it blocks via `entity_vec` KNN in space S and merges only on unique linguistic corroboration, otherwise writes `close_matches`; `aliases.status` is retired; $P(e \mid a)$ is backed by `aliases` + `close_matches`.\
**Governing Canon:** [`FOUNDATIONAL.md §3, §5.1, §5.2`](../../FOUNDATIONAL.md), [`docs/adr/ADR-010.md`](ADR-010.md), [`docs/epics-alignment-roadmap.md §7.1`](../epics-alignment-roadmap.md)\
**Implementation:** [`src/yaw/indexer/canonicalize.py`](../../src/yaw/indexer/canonicalize.py), [`src/yaw/storage/db.py`](../../src/yaw/storage/db.py), [`src/yaw/config.py`](../../src/yaw/config.py)

---

### Context & Problem Statement

Extracted entity mentions and relation predicates exhibit high lexical entropy across independent markdown notes (e.g., "Albert Einstein", "A. Einstein", "Einstein", or "special-relativity" vs "Einsteinian relativity"). If left uncanonicalized, the knowledge graph fragments into disconnected synonym islands, defeating multi-hop Personalized PageRank (PPR) traversal and conductances.

Prior prototypes attempted a 3-tier resolver combining `difflib.SequenceMatcher` lexical fuzzy matching, `sqlite-vec` canopy scans, and an expensive Tier 3 LLM pairwise comparator (`_adjudicate_pair_with_llm` invoking Ollama `/api/chat`).
This historical design created severe architectural and performance bottlenecks:
1. **Prohibitive LLM Overhead:** Invoking an LLM pairwise comparator for borderline candidates introduces $\mathcal{O}(N \times M)$ latency, non-deterministic ingestion stalling, and token exhaustion.
2. **Procedural Code Smells:** $\mathcal{O}(N)$ procedural `difflib.SequenceMatcher` loops, unindexed BLOB scan ladders (`_scan_candidates_in_memory()`), and mutable verdict caches created CPU bottlenecks during re-indexing.
3. **Obsolete Enum Pollution:** Deprecated variants (`TIER_3_LLM`, `TIER_1_LEXICAL`, `FALLBACK_NEW`, `MatchMethod.LLM`, `MatchMethod.LEXICAL`, `MatchMethod.COMPILE`) leaked obsolete procedural and LLM execution states into type definitions.
4. **Premature Discretization:** Forcing every ambiguous surface form into a single greedy binary match dropped polysemous candidate hypotheses, corrupting graph canopy seeding.

### Decision

Deprecate the 3-tier procedural resolver and adopt the **Two-Tier Convergence Engine** backed by spaCy's native compiled C/Cython **`InMemoryLookupKB`** in [`src/yaw/indexer/canonicalize.py`](../../src/yaw/indexer/canonicalize.py):

```
Surface Form Mention (name, kind, namespace)
               │
               ▼
┌────────────────────────────────────────────────────────┐
│ Tier 1: Direct Match (Compiled C/Cython KB & SQLite)   │──[Match Found]──► Resolved Canonical Node
│ - Exact slug in leaf_nodes                             │                   (TierEnum.TIER_1_EXACT)
│ - Hard alias in aliases (owl:sameAs)                   │                   (MatchMethod.EXACT / ALIAS)
│ - leaf_relations / config.BASE_PREDICATES              │
│ - InMemoryLookupKB.get_alias_candidates(clean_name)    │
└────────────────────────────────────────────────────────┘
               │ [No Direct Match]
               ▼
┌────────────────────────────────────────────────────────┐
│ Tier 2: Blocked + Corroborated (ADR-012, spaces S + L) │──[1 corroborated]─► Merge into Canonical Node
│ - entity_vec KNN (Gemma sentence similarity, space S)  │                   - _record_alias(method="auto")
│ - Keep cosine >= CANON_SIM_THRESHOLD (0.80)            │                   - (TierEnum.TIER_2_EMBEDDING)
│ - Corroborate: acronym / head containment / initials   │                   - (MatchMethod.AUTO)
│ - Every pair logged to canon_verdicts                  │
└────────────────────────────────────────────────────────┘
               │ [0 or ≥2 corroborated: close_matches soft links, no merge]
               ▼
┌────────────────────────────────────────────────────────┐
│ Fallback: Novel Canonical Induction                    │──► Create Canonical Node
│ - _create_canonical_node(namespace="concepts")         │    (TierEnum.NEW_INDUCTION)
│ - Register in leaf_nodes & InMemoryLookupKB            │    (MatchMethod.NEW, is_new=True)
└────────────────────────────────────────────────────────┘
```

1. **Native Cython `InMemoryLookupKB` Integration & Candidate Prior Distributions:**
   - Rather than ad-hoc python dictionaries or procedural string matching, candidate entity and alias lookup is powered by spaCy's native `InMemoryLookupKB`.
   - `InMemoryLookupKB` is the **alias → candidate prior index** (never a similarity source, [ADR-012 §1](ADR-012.md)). It maintains a normalized candidate distribution $P(\text{entity } e \mid \text{alias } a) \in (0, 1]$ (normalized evidence weights, not calibrated probabilities) satisfying:
     $$\sum_{e \in \text{cands}(a)} P(e \mid a) = 1.0$$
   - Synchronized seamlessly from the database via `sync_kb_from_db(kb, conn)`:
     - Canonical nodes from `leaf_nodes` are registered as KB entities. KB entity vectors are never used for cosine comparison.
     - Base predicates and relation predicates are registered as canonical identities.
     - Candidates are built from `aliases` (hard canonical, $w = 1$) and `close_matches` ($w = \text{score}$), normalized, and registered via `kb.add_alias(alias, entities, probabilities)` ([ADR-012 §3](ADR-012.md)).
   - Microsecond alias evaluation: `kb.get_alias_candidates(alias)` returns compiled candidates directly in C/Cython without Python overhead.

2. **Purge of Obsolete Enum Variants & Verdict Records:**
   - All references to `CanonicalVerdict` and live pairwise adjudication tables during canonicalization are eliminated.
   - Enums are strictly pruned to canonical production states:
     ```python
     class TierEnum(str, Enum):
         TIER_1_EXACT = "tier_1_exact"
         TIER_2_EMBEDDING = "tier_2_embedding"
         NEW_INDUCTION = "new_induction"


     class MatchMethod(str, Enum):
         EXACT = "exact"
         ALIAS = "alias"
         AUTO = "auto"
         NEW = "new"
     ```
   - Obsolete variants (`TIER_3_LLM`, `TIER_1_LEXICAL`, `FALLBACK_NEW`, `MatchMethod.LLM`, `MatchMethod.LEXICAL`, `MatchMethod.COMPILE`) are completely removed from the engine.

3. **Tier 1: Direct Match (Zero Cost):**
   - **Knowledge Base Lookup:** Checks candidates in `InMemoryLookupKB` via `_lookup_kb(name, kb)`. If candidate exists, resolves immediately as `TierEnum.TIER_1_EXACT` with `MatchMethod.EXACT` or `MatchMethod.ALIAS`.
   - **Exact Slug, Normalized Key & Alias:** Inspects the `aliases` table (hard identity only; the former `status` column is retired by [ADR-012](ADR-012.md)) for mappings matching `surface_id`, `slug`, the spaCy normalized key, or raw `name`.
   - **Direct Entity / Predicate Tables:** Checks exact node slug matches in `leaf_nodes`, or direct base predicate matches in `config.BASE_PREDICATES` and `leaf_relations`.
   - Resolves immediately as `TierEnum.TIER_1_EXACT` with `score=1.0`.

4. **Tier 2: Blocked Candidate Generation + Corroborated Matching ([ADR-012 §2](ADR-012.md)):**
   - **Blocking (space S):** retrieves the top-`CANON_TOP_K` neighbours from `entity_vec` (EmbeddingGemma, `task: sentence similarity` prompt), restricted to the mention's namespace partition plus active ontology partitions, keeping candidates with cosine $\ge$ `CANON_SIM_THRESHOLD` (τ, default 0.80, an uncalibrated prior).
   - **Matching (space L):** a candidate is a merge candidate only if a deterministic linguistic corroboration holds: acronym, head-anchored containment, or initial expansion.
   - If **exactly one** merge candidate exists, the mention is merged via `_record_alias(conn, alias_id=surface_id, canonical_id=best_cand_id, method="auto", score=best_cosine, kb=kb)` and resolves as `TierEnum.TIER_2_EMBEDDING` with `method="auto"`, `is_new=False`.
   - **Otherwise** (zero or ≥2 merge candidates), no merge occurs: every candidate with cosine $\ge \tau$ becomes a soft link in `close_matches`, and the mention keeps its own node.
   - Every evaluated pair is logged to `canon_verdicts`.
   - **Predicates never enter Tier 2.** They resolve in space L only (lemma → synset / alias dictionary → base predicate → polarity-guarded static-vector fallback onto the base predicates), with zero embedding calls.

5. **Fallback: Novel Canonical Node Creation:**
   - Mentions failing both Tier 1 and Tier 2 merges create a new canonical identity via `_create_canonical_node()` persisting to `leaf_nodes` when a `source_leaf_id` is present.
   - Registers the novel canonical entity into `InMemoryLookupKB` and writes one space-S vector for it to `entity_vec`.
   - Resolves as `TierEnum.NEW_INDUCTION` with `method="new"`, `is_new=True`.

6. **Complete Elimination of Tier 3 LLM Pairwise Adjudication:**
   - Eliminate all live LLM pairwise adjudication during canonicalization (0 LLM calls during entity or predicate canonicalization).
   - Delete dead procedural code: remove `_scan_candidates_in_memory()` and $\mathcal{O}(N)$ `difflib.SequenceMatcher` loops.

7. **Decoupled View Rewiring:**
   - Hard identity is stored in the `aliases` table (`alias_id`, `kind`, `canonical_id`, `method`, `score`, `source_leaf_id`); soft identity candidates are stored in `close_matches` ([ADR-012](ADR-012.md)).
   - The `aliases.score` column is 1.0 for Tier 1 and the space-S cosine for a corroborated Tier 2 merge. The candidate distribution $P(e \mid a)$ that feeds GraphRAG PPR seeding and topological disambiguation is derived from `aliases` + `close_matches` ([`docs/adr/ADR-010.md`](ADR-010.md), [ADR-012 §3](ADR-012.md)).
   - Dynamic SQLite views (`unified_nodes`, `unified_edges`) route node and edge endpoints directly to `canonical_id` without destructive mutations to raw chunk or leaf records.

### Consequences & Trade-offs

- **Positive:** Zero LLM calls during entity or predicate canonicalization, eliminating network roundtrips, token costs, and timeout risks during continuous indexing.
- **Positive:** In-process compiled C/Cython candidate generation through `InMemoryLookupKB` achieves microsecond lookup speeds.
- **Positive:** Native preservation of alias candidate distributions $P(e \mid a) \in (0, 1]$ prevents premature winner-take-all discretization, laying the mathematical foundation for topological disambiguation in GraphRAG ([`docs/adr/ADR-010.md`](ADR-010.md)).
- **Positive:** Type-safe, purged enums: `TierEnum` and `MatchMethod` strictly reflect reality without obsolete dead variants.
- **Positive:** Deterministic merge decisions (Tier 1 rules and Tier 2 linguistic corroboration) over exact alias graphs.
- **Trade-off:** True synonyms with no lexical overlap (e.g. "car" / "automobile") are not merged; they persist as separate canonical nodes connected by weighted `closeMatch` edges ([ADR-012](ADR-012.md)).
