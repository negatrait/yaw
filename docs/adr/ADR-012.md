### Context & Problem Statement

An audit of the Epic 7.6 code (2026-10-11) found that one column, `leaf_nodes.embedding`, was written in one vector space and read as if it held another:

| Path | Space actually used |
| :--- | :--- |
| `pipeline._resolve_and_store_nodes` writes `leaf_nodes.embedding` | EmbeddingGemma 768d, `Classification` prompt |
| `loader._index_ontology_fts_and_vectors` writes `leaf_nodes.embedding` | EmbeddingGemma 768d, `Classification` prompt (NULL when offline) |
| `sync_kb_from_db` reads it into `InMemoryLookupKB` (width 300) | Length check fails → **zero vector** for every ingested entity |
| Tier 2 for predicates (`_find_vec_nearest`) | 300d GloVe query vs 768d rows → dimension error swallowed at `debug` |
| Retrieval concept seeding (`compute_seed_vector`) | `Retrieval-query` prompt vs `Classification`-prompt vectors |

The root cause is not a bug in one function. The canon ([`FOUNDATIONAL.md §3`](file:///home/harri/yaw/FOUNDATIONAL.md)) assigned representations **per model** ("Gemma for chunks, spaCy for everything else") instead of **per job**. The three jobs have different correctness criteria, and no single representation satisfies all three:

1. **Predicate canonicalization** is closed-set classification onto 14 base predicates, where *polarity* is the dominant failure mode. Distributional vectors place antonyms close together ([Mrkšić et al., 2016](https://aclanthology.org/N16-1018/)), which is why YAW already needs a polarity exclusion mask. The value spaCy brings here is **linguistic structure** (lemmas, dependency parse, negation), not its vectors.
2. **Entity identity** is a precision problem. Distributional and neural similarity both measure *relatedness*, which is not *identity* ([Hill et al., 2015, SimLex-999](https://aclanthology.org/J15-4004/)). For example, "Barack Obama" and "Michelle Obama" score high. In a PPR graph, a false merge is a false bridge, and probability mass crosses it. On multi-hop benchmarks that produces confidently wrong answers.
3. **Retrieval seeding** ranks graph elements by relevance to a natural-language question. That is the job an asymmetric retrieval encoder is trained for. An averaged GloVe vector of a question is an unordered bag of words.

Additionally, [`ADR-010`](file:///home/harri/yaw/docs/adr/ADR-010.md) claims multi-candidate alias distributions $P(e \mid a)$, but `aliases` has `PRIMARY KEY (alias_id, kind)`: storage can hold only one canonical per alias. The distribution therefore has no persistent backing.

### Evidence Base

| # | Source | Finding used here |
| :--- | :--- | :--- |
| E1 | [HippoRAG (Gutiérrez et al., 2024), §Offline Indexing & §Ablations](https://arxiv.org/abs/2405.14831) | The retrieval encoder adds **synonymy edges** between phrase nodes whose cosine exceeds a threshold τ. It does not merge them. Ablation: *"synonymy edges have the largest effect on 2WikiMultiHopQA, suggesting that noisy entity standardization is useful when most relevant concepts are named entities."* |
| E2 | [HippoRAG 2 (Gutiérrez et al., 2025), §3.3, §6.1](https://arxiv.org/abs/2502.14802) | Query-to-triple linking improves Recall@5 by **12.5%** on average over NER-to-node. It *"consistently outperforms the other two linking strategies"* **regardless of whether LLM filtering is applied**. Query-to-node gives **no advantage**, *"as queries and KG nodes operate at different levels of granularity."* |
| E3 | [HippoRAG 2, §3.5, §6.2](https://arxiv.org/abs/2502.14802) | Phrase seeds take *"their average ranking scores across filtered triples they originate"*. The passage-vs-phrase reset weight factor *"is crucial for the PPR results"*. Their default of 0.05 was tuned on their validation set. |
| E4 | [EmbeddingGemma model card](https://ai.google.dev/gemma/docs/embeddinggemma/model_card) | Asymmetric retrieval: query `task: search result \| query: {content}`, document `title: {title \| "none"} \| text: {content}` (*"providing a title, if available, will improve model performance"*). Semantic Similarity prompt `task: sentence similarity \| query: {content}` is *"not intended for retrieval use cases."* |
| E5 | [W3C SKOS Reference §10, S38–S44](https://www.w3.org/TR/skos-reference/#mapping) | `skos:closeMatch` links concepts *"sufficiently similar that they can be used interchangeably in some information retrieval applications"* and is **not transitive**, *"to avoid the possibility of 'compound errors'."* `skos:exactMatch` is transitive. Both are `owl:SymmetricProperty` (S44). Mapping properties are intended for concepts **in different concept schemes**. |
| E6 | [Papadakis et al., 2020, ACM CSUR 53(2)](https://doi.org/10.1145/3377455) | Entity resolution is decomposed into cheap high-recall **blocking** followed by precise **matching**, to avoid $\mathcal{O}(N^2)$ comparisons. |
| E7 | sqlite-vec v0.1.9 (installed; verified locally) | `vec0` virtual tables support `PARTITION KEY` columns, `distance_metric=cosine`, exact KNN via `MATCH ? AND k = ?`, and **reject dimension-mismatched inserts** with `OperationalError`. |

### Decision

#### 1. Three representation spaces, one job each

| Space | Representation | Job | Stores | Forbidden uses |
| :--- | :--- | :--- | :--- | :--- |
| **L: Linguistic** | spaCy `en_core_web_lg` pipeline: tokenizer, lemmatizer, parser, NER, polarity mask; static 300d vectors only as the last, polarity-guarded tier onto the 14 base predicates | Predicate canonicalization; Tier 1 normalization keys; query mention extraction | In-process only | Entity similarity; retrieval |
| **S: Symmetric similarity** | EmbeddingGemma 768d, prompt `task: sentence similarity \| query: {name}: {definition}` | Entity-identity **candidate generation** (Tier 2 blocking) and soft identity links | `entity_vec` (`vec0`, partitioned by namespace) | Retrieval of any kind (E4) |
| **R: Asymmetric retrieval** | EmbeddingGemma 768d; documents `title: {note_title \| none} \| text: {content}`, queries `task: search result \| query: {query}` | Query → chunk and query → fact relevance | `note_chunks.embedding`, `fact_vec` (`vec0`) | Entity identity decisions |

Rules:
- A vector column holds exactly one space. Every new vector store is a `vec0` table, so a dimension mismatch fails loudly at insert (E7).
- A similarity is computed only between two vectors of the same space, with the prompt pairing the space prescribes.
- `InMemoryLookupKB` is the **alias → candidate prior index**. It is not a similarity source: no code path computes cosine against KB entity vectors.
- Zero LLM (generative) calls in canonicalization and retrieval. EmbeddingGemma is an encoder, and its calls are batched.

#### 2. Identity resolution: Tier 1 decides, Tier 2 proposes

**Tier 1: Deterministic identity (space L, $\mathcal{O}(1)$).** A surface form resolves to an existing canonical node if one of these matches:
- an exact `canonical_id`;
- its **normalized key**: NFKC + casefold, leading determiner removed, possessive clitic removed, `NOUN` tokens lemmatized (`PROPN` kept verbatim), punctuation, hyphens and whitespace collapsed;
- an existing row in `aliases`;
- an ontology `skos:prefLabel` / `skos:altLabel` / `rdfs:label` alias (`method = 'ontology'`).

Tier 1 alone absorbs the case, plural, punctuation and article variants that make up the bulk of surface duplication, at zero vector cost.

**Tier 2: Blocked candidate generation + corroborated matching (spaces S and L).**
1. **Blocking (E6):** retrieve the top-`CANON_TOP_K` (default 5) neighbours from `entity_vec` in space S, restricted to partitions of the mention's namespace plus the namespaces of active target ontologies. Keep candidates with cosine $\ge \tau$ (`CANON_SIM_THRESHOLD`).
2. **Matching:** a candidate $e$ is a **merge candidate** for mention $a$ only if a deterministic linguistic corroboration $\mathcal{L}(a, e)$ also holds. Any one of these is enough:
   - **acronym:** one side is a single upper-case token of length 2–6 equal to the initials of the other side's content tokens;
   - **head-anchored containment:** one token sequence is a contiguous subsequence of the other, and both share the syntactic head (`Span.root`), e.g. "Einstein" ⊂ "Albert Einstein";
   - **initial expansion:** token-aligned match where initials match full tokens, e.g. "A. Einstein" ↔ "Albert Einstein".
3. **Decision:**
   - **Exactly one** merge candidate → **hard merge**: `aliases` row, `method = 'auto'`, `score = cosine`. Projects to `owl:sameAs`.
   - **Otherwise** (zero, or ≥2 merge candidates) → **no merge**. Every candidate with cosine $\ge \tau$ becomes a **soft link** in `close_matches(src_id, dst_id, score)`. The mention keeps its own node.
4. **Audit:** every evaluated pair is logged to `canon_verdicts` (`cosine`, `lexical ∈ {0, 1}`, `verdict ∈ {match, distinct}`). That log is the labelled data used to calibrate τ.

**Predicates never enter Tier 2.** They resolve by space L only: lemma → synset / alias dictionary → base-predicate match → polarity-guarded static-vector fallback onto the 14 base predicates. Anything still unmapped mints an open predicate `predicates:{lemma-slug}` (Quadrant 1) or is filtered by the view (Quadrant 2).

**Why soft links instead of merges.** A wrong merge cannot be undone without re-ingestion, and it creates a false bridge. A soft link only adds a weighted edge, and PPR resolves it topologically (ADR-010 §3). E1 measured that soft synonymy edges help most exactly where entities dominate (2WikiMultiHopQA). Hard merges are reserved for cases where linguistic evidence and vector evidence agree on a unique candidate.

**Retirement of `contested`.** Tier 2 no longer writes `aliases.status = 'contested'`. Ambiguity is now represented explicitly as **≥2 `close_matches` edges from one node whose targets are not linked to each other**. `aliases.status` is removed, and SHACL reports such nodes as `sh:Warning` "ambiguous identity" (an LLM-Wiki epistemic tension signal; see [`ADR-011`](file:///home/harri/yaw/docs/adr/ADR-011.md)).

#### 3. A storage-backed candidate distribution $P(e \mid a)$

For a resolved mention node $a$ with hard canonical $\hat{a}$:
$$\text{cands}(a) = \{\hat{a}\} \cup \{\, e : (\hat{a}, e) \in \texttt{close\_matches} \,\}, \qquad P(e \mid a) = \frac{w(a, e)}{\sum_{e'} w(a, e')}$$
with $w(a, \hat{a}) = 1$ and $w(a, e) = \text{score}(\hat{a}, e)$. `sync_kb_from_db` builds `InMemoryLookupKB.add_alias(alias, entities, probabilities)` from exactly this. ADR-010's distribution now has a persistent SSOT.

`close_matches` projects into `unified_edges` as `rel_type = 'closeMatch'` in **both directions** (symmetric, E5), with `weight = score`. It is an engine-owned structural edge, like `wikilink` and `mentions`, not one of the 14 canonical predicates.

#### 4. Query-to-fact seeding (space R)

- **Fact index:** every `leaf_relations` row gets one space-R document embedding in `fact_vec(relation_id PRIMARY KEY, embedding float[768])`. The text is rendered deterministically and never stored (Invariant 2): `title: {note_title} | text: {subject_name} {surface_predicate} {object_name}`. Fact embeddings are batched into the same `/api/embed` call as the chunk embeddings.
- **Seeding:** with $\mathbf{q}$ the space-R query vector and $F_q$ the top-`FACT_TOP_K` facts from `fact_vec`:
  $$r(q, e) = \operatorname*{mean}_{f \in F_q,\; e \in \{\text{subj}(f), \text{obj}(f)\}} \cos(\mathbf{q}, \mathbf{f}) \quad (0 \text{ if } e \text{ occurs in no } f \in F_q) \qquad \text{(E3)}$$
  $$\mathbf{s}_{\text{concepts}} = \lambda \cdot \widehat{\mathbf{s}}_{\text{alias}} + (1 - \lambda) \cdot \widehat{\mathbf{r}}, \qquad \mathbf{s}_{\text{alias}}[e] = \sum_{a \in M(q)} P(e \mid a)$$
  - $M(q)$ is the set of query mentions extracted in space L.
  - $\widehat{\cdot}$ denotes L1 normalization.
  - The two channels are **additive**, so an entity named in the question but absent from the top facts still seeds (it is typically the first hop).
- **Removed:** query → `leaf_nodes` vector seeding. It is the query-to-node strategy (no advantage per E2), and its vectors are not in space R anyway (E4).
- **Offline degradation** stays continuous. With $\mathbf{q} = \mathbf{0}$, $\mathbf{r} = \mathbf{0}$, so $\mathbf{s}_{\text{concepts}} = \widehat{\mathbf{s}}_{\text{alias}}$ and $\mathbf{s}_{\text{chunks\_vec}} = \mathbf{0}$.
- **Hyperparameters:** $\lambda$, $\beta_{1..3}$, `FACT_TOP_K` and τ are **uncalibrated priors** (initial values λ = 0.5, `FACT_TOP_K` = 5, τ = 0.80, β = 0.6/0.2/0.2). E3 shows the passage/phrase balance is decisive. Calibration on a benchmark calibration split only, with reporting on a disjoint held-out split, is part of the Epic 8 evaluation protocol.

#### 5. External ontology classes

- Ontology classes are **not** written to `leaf_nodes`. That table holds only note extractions (Invariant 1).
- Each class gets one space-S vector in `entity_vec`, partitioned by its ontology prefix. That makes it a Tier 2 candidate for note mentions while that ontology is active.
- A note mention reaches an ontology class in one of two ways:
  - a hard merge, via Tier 1 label aliases or a corroborated Tier 2 match; or
  - a `close_matches` edge. Such an edge **instantiates** a ghost class and admits it into the PPR graph.
- Ontology labels and definitions remain in `query_fts` (ADR-011 §4). Re-ingesting the same ontology replaces its rows rather than duplicating them.
- RDF projection of `close_matches`:
  - **Cross-scheme** (vault ↔ external ontology): `skos:closeMatch` (E5).
  - **Intra-vault**: `yaw:closeMatch`, declared `owl:SymmetricProperty`, **not** transitive and **not** a sub-property of `skos:closeMatch`, because SKOS mapping properties are intended for different concept schemes (E5).
  - Hard merges: `owl:sameAs`.
  - `canon_verdicts`: **not projected**. Under this protocol `distinct` means "not merged" (insufficient corroboration), not evidence of non-identity. Emitting `owl:differentFrom` would be unsound under the open-world assumption, and any later `owl:sameAs` for the pair (e.g. a new ontology label alias) would derive `false` by OWL 2 RL rule `eq-diff1` ([OWL 2 Profiles §4.3, Table 4](https://www.w3.org/TR/owl2-profiles/#Reasoning_in_OWL_2_RL_and_RDF_Graphs_using_Rules)).

### Cost Model (per ingestion and per query)

| Operation | Before | After |
| :--- | :--- | :--- |
| Entity embedding | 1 Gemma call per node (`Classification` prompt) | 1 Gemma call per **new canonical** node (`sentence similarity` prompt). Net ≤ before. |
| Fact embedding | — | 1 short document embedding per fact, batched with the chunk call |
| Tier 2 search | Full-table `vec_distance_cosine` scan per mention, unpartitioned | `vec0` exact KNN, `k = 5`, one namespace partition (E7) |
| Tier 1 | slug + alias lookup | slug + spaCy normalized key + alias lookup (in-process) |
| LLM calls in canonicalization / retrieval | 0 | 0 |
| Query | 1 query embedding, chunk KNN, leaf-node scan | 1 query embedding, chunk KNN, fact KNN (`k = FACT_TOP_K`) |

### Consequences

**Positive**
- Each column has one vector space, so dimension mismatches fail at insert instead of being swallowed.
- False bridges from relatedness-based auto-merges are eliminated. Ambiguity becomes explicit and topologically resolvable (ADR-010 §3).
- $P(e \mid a)$ gets a persistent, auditable backing (`close_matches`), and `canon_verdicts` becomes the labelled calibration set for τ.
- Retrieval seeding adopts the linking strategy with the strongest published evidence on MuSiQue and 2WikiMultiHopQA (E2).

**Negative & Mitigations**
- *Duplicate nodes persist where corroboration fails* (e.g. true synonyms with no lexical overlap: "car" / "automobile"). Mitigation: they are connected by weighted `closeMatch` edges, so PPR mass flows between them. `compile_wiki` renders them as "see also" links rather than one merged page.
- *Extra ingestion cost* of one embedding per fact. Mitigation: batched with chunk embedding. Facts are short.
- *The normalized key changes canonical slugs* for existing vaults. Mitigation: aliases from old slugs to new keys are written during the one-time Epic 7.7 migration. `vault/raw/` is untouched (Invariant 1).
- *Hyperparameters are uncalibrated* until Epic 8. Mitigation: the dev-only calibration protocol is mandated above. No headline numbers before calibration.
