###### Abstract.

Multi-hop retrieval-augmented generation (RAG) supports Web information seeking and fact verification by recovering complementary evidence across related pages within a limited retrieval budget. Scoring evidence independently against the original question can miss supporting units whose relevance emerges through intermediate facts. Iterative retrieval incorporates these facts into subsequent queries, while graph retrieval explicitly models relations among evidence units. Yet fixed-query graph retrievers update entity representations without adapting the query condition to accumulated relational context. We view multi-hop evidence recovery as the coupled evolution of evidence representations and query conditions, with accumulated context informing both what the retriever represents and how it searches for complementary evidence. QueryFlow realizes this perspective by recurrently integrating query-conditioned summaries of graph context into a shared query state, which controls boundary inputs and relation features for subsequent propagation. Across four representative multi-hop question answering (QA) datasets, QueryFlow achieves macro Recall@10 (R@10), Full Recall@10 (FR@10), and LLM-Acc gains of 4.98, 8.40, and 8.0 percentage points over representative baselines, respectively.

###### Keywords:

GraphRAG, graph neural networks, graph-based retrieval, multi-hop question answering, web content mining

## 1. Introduction

Retrieval-augmented generation (RAG) grounds language-model answers in external evidence ([Lewis et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib31)). In Web content mining, it supports complex information seeking and fact verification across related pages ([Talmor and Berant, 2018](https://arxiv.org/html/2611.04625v1#bib.bib53); [Jiang et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib54)). Multi-hop questions make this evidence requirement more demanding because their answers depend on linked facts distributed across pages about related entities ([Ho et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib4); [Trivedi et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib5); [Yang et al., 2018](https://arxiv.org/html/2611.04625v1#bib.bib3)). Answering these questions requires retrieving evidence units, such as documents, passages, or chunks, that jointly support the necessary reasoning steps. A collection of individually relevant units can still omit a fact needed to complete the reasoning chain. Multi-hop retrieval is fundamentally an evidence-set recovery problem, with the goal of recovering the complete supporting set within a given retrieval budget. By improving multi-hop question answering over interconnected Web content, our work aligns with the Web Mining, Multimedia and Multilingual Content Analysis track.

Recovering a complete supporting set requires more than matching individual evidence units to the original question. Single-round dense retrievers learn semantic matches between questions and candidate evidence ([Karpukhin et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib32)), but independent scoring can miss complementary units whose relevance becomes apparent only after intermediate facts are found. Iterative retrieval addresses this limitation by conditioning subsequent searches on retrieved passages or intermediate reasoning ([Xiong et al., 2021](https://arxiv.org/html/2611.04625v1#bib.bib7); [Trivedi et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib2)). In these approaches, evidence dependencies are conveyed through retrieval history, leaving entity relations across documents implicit. Graph-based RAG makes these connections explicit through entities and relations ([Edge et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib17); [Zhu et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib27)), while neural graph retrievers learn to integrate connected evidence through query-conditioned message passing ([Li et al., 2025b](https://arxiv.org/html/2611.04625v1#bib.bib52); [Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)). A central question in learned graph retrieval is how accumulated relational context should guide subsequent evidence acquisition. Fixed-query designs update entity representations while retaining the original query condition ([Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)). As illustrated in Figure [1](https://arxiv.org/html/2611.04625v1#acmlabel1 "Figure 1 ‣ 1. Introduction ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution"), identifying the author of The Hobbit shifts the remaining information need toward that person’s birthplace, while a fixed query can continue to favor book-related evidence. These designs accumulate relational context in entity representations without an explicit feedback path for that context to revise the query condition governing subsequent propagation.

The query state should evolve with the evidence representations it guides. Intermediate entities and relations can clarify what remains to be retrieved, so accumulated graph context should inform both the representation of evidence and the condition used to explore further evidence. Coupling these updates brings relational propagation and query adaptation into the same retrieval process, allowing newly established context to guide the recovery of missing support.

We introduce QueryFlow, a graph retrieval framework that couples recurrent query evolution with evidence propagation to support multi-hop question answering. It maintains a shared query state alongside entity representations that accumulate relational context through message passing. Between successive propagation layers, query-conditioned attention summarizes all entity representations, making context distributed across the graph available to the query update. A gated recurrent transition integrates this summary with the preceding query state to revise the retrieval condition. Boundary feedback injects the updated state at question-linked entities, while relation feedback modulates the features used to transform neighboring messages. These interfaces change both the context injected into the graph and how evidence propagates across its relations, closing the feedback path from accumulated evidence to subsequent retrieval. Finally, entity scores are aggregated into a document ranking that supplies evidence for answer generation.

On four representative multi-hop QA datasets, QueryFlow achieves macro R@10, FR@10, and LLM-Acc gains of 4.98, 8.40, and 8.0 percentage points over representative baselines, respectively. Improvements in evidence coverage and complete recovery are accompanied by higher downstream QA reasoning accuracy, supporting the value of complete evidence retrieval for multi-hop question answering.

Our contributions are threefold.

- •

  We frame multi-hop graph retrieval as coupled evolution of evidence representations and query conditions, treating accumulated relational context as feedback for subsequent evidence acquisition.

- •

  We propose QueryFlow, which couples recurrent query updates with graph propagation through boundary and relation feedback.

- •

  Experiments on four multi-hop QA benchmarks show gains over representative baselines in evidence recovery and answer accuracy.

## 2. Related Work

Relevance-based retrieval. RAG integrates external evidence into language-model training or generation ([Lewis et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib31); [Guu et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib33); [Borgeaud et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib36); [Izacard et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib35)). Dense representations and token interactions improve matching between questions and evidence ([Karpukhin et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib32); [Izacard et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib37); [Khattab and Zaharia, 2020](https://arxiv.org/html/2611.04625v1#bib.bib38); [Santhanam et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib14)). Precomputed passage representations support efficient search, while token-level interactions retain fine-grained matching signals within each candidate passage. Better query representations, evidence fusion, and hierarchical indexing further improve evidence access and use ([Gao et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib13); [Izacard and Grave, 2021](https://arxiv.org/html/2611.04625v1#bib.bib34); [Shi et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib43); [Sarthi et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib12)). In single-round matching, retrieved evidence does not update the scoring condition, so complementary support with weak direct relevance can be missed. QueryFlow complements relevance scoring with feedback from accumulated relational context.

Iterative and adaptive retrieval. Iterative retrievers use retrieved passages, condensed facts, or rewritten queries to guide later searches ([Qi et al., 2019](https://arxiv.org/html/2611.04625v1#bib.bib39); [Zhang et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib41); [Ma et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib42)). MDR re-encodes the question with earlier passages ([Xiong et al., 2021](https://arxiv.org/html/2611.04625v1#bib.bib7)), while Baleen condenses retrieved passages into facts for later hops ([Khattab et al., 2021](https://arxiv.org/html/2611.04625v1#bib.bib40)). Intermediate generation and reasoning also supply feedback ([Shao et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib44); [Trivedi et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib2)), while adaptive approaches control when and how to retrieve based on generation state or question difficulty ([Jiang et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib23); [Su et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib45); [Asai et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib24); [Jeong et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib25)). In retrieval loops driven by passages or reasoning, feedback passes through text history, leaving entity relations across documents implicit. QueryFlow brings this adaptation into graph propagation, using intermediate entity context to update the shared retrieval condition.

Graph-based retrieval. Knowledge graph research also studies graph completion, which predicts missing entities or relations from graph structure. Completion methods learn multi-concept and fine-grained entity–relation representations ([Wang et al., 2023a](https://arxiv.org/html/2611.04625v1#bib.bib61); [Wang et al., 2024c](https://arxiv.org/html/2611.04625v1#bib.bib64)), or adapt how entity, relation, and temporal information is combined to predict missing facts ([Wang et al., 2023b](https://arxiv.org/html/2611.04625v1#bib.bib63); [Wang et al., 2024a](https://arxiv.org/html/2611.04625v1#bib.bib62); [Wang et al., 2024d](https://arxiv.org/html/2611.04625v1#bib.bib65)). Broader graph representation learning combines local and global signals for node classification, while attributed graph clustering uses collaborative graph augmentation and contrastive learning ([Wang et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib66); [Zhao et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib67)). These tasks learn graph representations or predict missing facts, whereas graph retrieval ranks source documents to recover evidence supporting a question.
Graph indices and diffusion associate evidence through explicit links ([Edge et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib17); [Guo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib16); [Zhu et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib27); [Gutiérrez et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib26); [Gutiérrez et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib19)), while subgraph selection and path exploration construct structured context ([He et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib15); [Hu et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib46); [Li et al., 2025a](https://arxiv.org/html/2611.04625v1#bib.bib48); [Sun et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib28); [Luo et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib29); [Luo et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib49)). Learned relational reasoning supports query-conditioned propagation ([Zhu et al., 2021](https://arxiv.org/html/2611.04625v1#bib.bib6); [Zhu et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib51); [Galkin et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib30); [Zhuo et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib60); [Wang et al., 2024b](https://arxiv.org/html/2611.04625v1#bib.bib59)), and neural retrievers learn to aggregate or select connected evidence ([Sun et al., 2019](https://arxiv.org/html/2611.04625v1#bib.bib50); [Mavromatis and Karypis, 2025](https://arxiv.org/html/2611.04625v1#bib.bib47); [Li et al., 2025b](https://arxiv.org/html/2611.04625v1#bib.bib52)). Learned graph retrievers differ in how relational context conditions retrieval. GFM-RAG propagates entity relevance under a fixed query and maps it to documents ([Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)), whereas D-RAG updates instructions from graph context for knowledge graph question answering ([Gao et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib55); [Zhuo et al., 2025b](https://arxiv.org/html/2611.04625v1#bib.bib57); [Zhuo et al., 2025a](https://arxiv.org/html/2611.04625v1#bib.bib58)). QueryFlow studies this interaction for complete document evidence recovery, using a shared evolving query state to control boundary inputs and relation features.

Overview. QueryFlow organizes multi-hop evidence retrieval as a feedback process between entity representations and a shared query state (Figure [2](https://arxiv.org/html/2611.04625v1#acmlabel2 "Figure 2 ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")). Entity propagation aggregates relational context, while recurrent query evolution converts that context into the condition for subsequent propagation. The evolving query state controls both boundary inputs and relation features, allowing accumulated context to influence how further evidence is explored. Final entity scores are aggregated into a document ranking for answer generation.

### 3.1. Evidence Graph and Query Grounding

Retrieval task and graph interface. Given a question $x$ and a document corpus $D$, the objective is to recover the set of supporting documents $D^{*}(x)\subseteq D$ within a retrieval budget $k$. The first $k$ documents in the output ranking form $\widehat{D}_{k}(x)$. We represent the corpus by an entity graph $G=(V,E,\mathcal{R})$ ([Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)), where $V$ contains entities and $E$ contains edges labeled by relation types in $\mathcal{R}$. An incidence matrix $A\in\{0,1\}^{&#124;V&#124;\times&#124;D&#124;}$ records associations between entities and documents, with $A_{ij}=1$ when entity $i$ occurs in document $j$. Message passing accumulates context at entity nodes; the incidence matrix subsequently transfers entity relevance to documents.

Query and entity initialization. A frozen text encoder produces question and relation embeddings $e_{x}$ and $e_{r}$. Learned linear projections $\phi_{q}$ and $\phi_{r}$ map them to a common $d$-dimensional space. Let $m_{x}\in\{0,1\}^{&#124;V&#124;}$ identify the entities linked to $x$. The initial query, relation features, and entity states are

| (1) |  | $\displaystyle q_{0}$ | $\displaystyle=\phi_{q}(e_{x}),\qquad R^{0}(r)=\phi_{r}(e_{r}),$ |  |
| --- | --- | ------------------------------ | ------------------------------ | --- |
|     |  | $\displaystyle H_{0}(i)$ | $\displaystyle=m_{x}(i)q_{0}.$ |  |

Thus entities linked to the question start from $q_{0}$, while other entities start from zero. At layer $l$, the shared query state $q_{l-1}\in\mathbb{R}^{d}$ controls the update to entity representations $H_{l}\in\mathbb{R}^{&#124;V&#124;\times d}$. The entity representations store context specific to each entity, while the query supplies a shared condition for propagation. Graph topology, document associations, and the grounding mask remain fixed as these representations evolve.

### 3.2. Query-Conditioned Evidence Propagation

Each layer propagates entity context using boundary inputs and relational messages ([Zhu et al., 2021](https://arxiv.org/html/2611.04625v1#bib.bib6)). The shared query state $q_{l-1}$ controls both the representations injected at question-linked entities and the relation features that transform neighboring messages.

Boundary feedback. The boundary input at the original grounding locations is

| (2) |  | $B_{l}(i)=m_{x}(i)q_{l-1}.$ |  |
| --- | --- | ------------------------------ | --- |

Its support is fixed by $m_{x}$, while its content changes with the query state. At later layers, this input reintroduces the context encoded by earlier query updates, maintaining a connection between question grounding and evolving relational information.

Relation feedback. The same state generates a gate for each feature of the base relation embeddings,

| (3) |  | $\displaystyle\gamma_{l-1}$ | $\displaystyle=\sigma(W_{r}q_{l-1}+b_{r}),$ |  |
| --- | --- | ------------------------------ | ------------------------------ | --- |
|     |  | $\displaystyle\bar{R}_{l}(r)$ | $\displaystyle=\psi_{l}\!\left(R^{0}(r)\odot\gamma_{l-1}\right).$ |  |

Here $\sigma$ is the sigmoid function, $\odot$ denotes elementwise multiplication, and $\psi_{l}$ is a layer-specific two-layer MLP with an intervening ReLU. The gate is shared across relation types, each retaining its own base embedding $R^{0}(r)$. It modulates dimensions of the relation features according to the current query condition before the layer-specific transformation.

Relational message passing. Let $\mathcal{N}(i)$ contain pairs of source entities and relations $(j,r)$ with an edge from $j$ to $i$. DistMult messages ([Yang et al., 2015](https://arxiv.org/html/2611.04625v1#bib.bib9)) and sum aggregation combine neighboring states with the boundary to give

| (4) |  | $u_{l,i}=B_{l}(i)+\sum_{(j,r)\in\mathcal{N}(i)}H_{l-1}(j)\odot\bar{R}_{l}(r).$ |  |
| --- | --- | ------------------------------ | --- |

The next entity representation is obtained by transforming the concatenated previous state and aggregate, followed by a residual connection:

| (5) |  | $\displaystyle t_{l,i}$ | $\displaystyle=W_{l}[H_{l-1}(i);u_{l,i}]+c_{l},$ |  |
| --- | --- | ------------------------------ | ------------------------------ | --- |
|     |  | $\displaystyle H_{l}(i)$ | $\displaystyle=H_{l-1}(i)+\operatorname{ReLU}(\operatorname{LN}_{l}(t_{l,i})).$ |  |

Here $[\,;\,]$ denotes concatenation, and $\operatorname{LN}_{l}$ is layer-specific normalization. Boundary feedback changes the representation injected at the starting entities, while relation feedback changes the features used to carry messages along edges. For $l<L$, $H_{l}$ supplies the next layer’s node input and the context for query evolution.

### 3.3. Graph-Conditioned Query Evolution

Query evolution summarizes $H_{l}$ to update the shared state $q_{l}$. For $l<L$, this state conditions the next propagation layer. The readout ablation additionally applies the same update at $l=L$ to $(H_{L},q_{L-1})$, obtaining the terminal state $q_{L}$ without further graph propagation.

Query-conditioned graph summary. We use the preceding query state to attend to the new entity representations with weights

| (6) |  | $a_{l,i}=\frac{\exp\!\left(H_{l}(i)^{\top}q_{l-1}/\sqrt{d}\right)}{\sum_{j\in V}\exp\!\left(H_{l}(j)^{\top}q_{l-1}/\sqrt{d}\right)}.$ |  |
| --- | --- | ------------------------------ | --- |

The normalized graph summary is

| (7) |  | $z_{l}=\operatorname{LN}_{\mathrm{sum}}\left(\sum_{i\in V}a_{l,i}H_{l}(i)\right).$ |  |
| --- | --- | ------------------------------ | --- |

The softmax ranges over all entities in $V$. Consequently, $z_{l}$ depends jointly on the current query and the graph representations, emphasizing context compatible with the retrieval condition. The summary provides an input of fixed width to the controller regardless of graph size.

Gated recurrent transition. A gated recurrent unit (GRU) ([Cho et al., 2014](https://arxiv.org/html/2611.04625v1#bib.bib1)) integrates $z_{l}$ with the preceding query state. An additional gate regulates the displacement in each feature dimension toward the candidate:

| (8) |  | $\displaystyle\widetilde{q}_{l}$ | $\displaystyle=\operatorname{GRUCell}(z_{l},q_{l-1}),$ |  |
| --- | --- | ------------------------------ | ------------------------------ | --- |
|     |  | $\displaystyle g_{l}$ | $\displaystyle=\sigma\!\left(W_{g}[q_{l-1};z_{l}]+b_{g}\right),$ |  |
|     |  | $\displaystyle\Delta_{l}$ | $\displaystyle=g_{l}\odot(\widetilde{q}_{l}-q_{l-1}).$ |  |

The candidate $\widetilde{q}_{l}$ combines previous query information with new graph context, while $g_{l}$ controls how much of their difference enters the update. A scalar $\alpha\in[0,1]$ scales this increment before query normalization:

| (9) |  | $q_{l}=\begin{cases}q_{l-1},&\alpha=0,\\ \operatorname{LN}_{q}(q_{l-1}+\alpha\Delta_{l}),&0<\alpha\leq 1.\end{cases}$ |  |
| --- | --- | ------------------------------ | --- |

We use $\alpha=1$ for recurrent propagation. Setting $\alpha=0$ retains $q_{l}=q_{0}$ by bypassing the transition and its normalization, providing a fixed-query intervention within the same model. The recurrent cell, transition gate, and relation gate share parameters across layers; $\operatorname{LN}_{\mathrm{sum}}$ and $\operatorname{LN}_{q}$ have separate parameters, each shared across layers. For $l<L$, the updated state controls the next boundary and relation features through Eqs. ([2](https://arxiv.org/html/2611.04625v1#S3.E2 "In 3.2. Query-Conditioned Evidence Propagation ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")) and ([3](https://arxiv.org/html/2611.04625v1#S3.E3 "In 3.2. Query-Conditioned Evidence Propagation ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")), completing the feedback from graph context to subsequent propagation.

### 3.4. Document Readout and Learning

Entity relevance scoring. After $L$ propagation layers, a shared two-layer MLP with an intervening ReLU scores each entity using its final representation and the initial query:

| (10) |  | $s_{i}=\operatorname{MLP}\!\left([H_{L}(i);q_{0}]\right).$ |  |
| ---- | --- | ------------------------------ | --- |

The default model uses $q_{0}$ in both training and retrieval to anchor scores to the original question. The readout ablation replaces $q_{0}$ with $q_{L}$ in Eq. ([10](https://arxiv.org/html/2611.04625v1#S3.E10 "In 3.4. Document Readout and Learning ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")), keeping $H_{L}$ unchanged. The entity-level objective trains the query controller through its influence on subsequent graph propagation.

Entity-to-document readout. We convert each entity logit $s_{i}$ into a positive contribution weight using

| (11) |  | $v_{i}=\operatorname{softplus}(s_{i})=\log(1+\exp(s_{i})).$ |  |
| ---- | --- | ------------------------------ | --- |

Let $f_{i}=\sum_{j=1}^{&#124;D&#124;}A_{ij}$ denote the document frequency of entity $i$. We assign reciprocal frequency weights ([Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)),

| (12) |  | $\displaystyle w_{i}^{\mathrm{doc}}$ | $\displaystyle=\begin{cases}f_{i}^{-1},&f_{i}>0,\\ 0,&f_{i}=0,\end{cases}$ |  |
| ---- | --- | ------------------------------ | ------------------------------ | --- |
|      |  | $\displaystyle d_{j}$ | $\displaystyle=\sum_{i\in V}A_{ij}\,w_{i}^{\mathrm{doc}}v_{i}.$ |  |

The readout aggregates contributions from all entities associated with each document. For entities that occur in many documents, reciprocal frequency weighting reduces their contribution to each document. We rank documents by $d_{j}$ and return the top $k$ as $\widehat{D}_{k}(x)$.

Entity-level learning. Let $y_{i}\in\{0,1\}$ be an entity supporting label and $P=\{i:y_{i}=1\}$ the positive set. With $p_{i}=\sigma(s_{i})$, the listwise loss that assigns normalized score mass to each supporting entity is

| (13) |  | $\displaystyle\pi_{i}$ | $\displaystyle=\frac{p_{i}}{\sum_{j\in V}p_{j}+\varepsilon},$ |  |
| ---- | --- | ------------------------------ | ------------------------------ | --- |
|      |  | $\displaystyle\mathcal{L}_{\mathrm{ListCE}}$ | $\displaystyle=-\frac{1}{&#124;P&#124;}\sum_{i\in P}\log(\pi_{i}+\varepsilon).$ |  |

Here $\varepsilon$ is a numerical stabilizer. We combine the listwise objective with a weighted binary cross-entropy term that classifies individual entities and emphasizes negatives with high scores to obtain

| (14) |  | $\mathcal{L}_{x}=0.3\,\mathcal{L}_{\mathrm{BCE}}+0.7\,\mathcal{L}_{\mathrm{ListCE}}.$ |  |
| ---- | --- | ------------------------------ | --- |

Gradients from entity scores jointly train graph propagation and the recurrent controller. Aggregation of entity scores into document scores and document ranking are applied at inference. Appendix [B](https://arxiv.org/html/2611.04625v1#A2 "Appendix B Training Objective and Retrieval Algorithm ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution") details the training objective and retrieval algorithm.

## 4. Experiments

Our experiments connect answer quality to the recovery of supporting evidence. We first compare generation and retrieval performance, then examine query evolution and its feedback interfaces through controlled interventions. Efficiency, retrieval budgets, and paired recovery analyses characterize the costs and conditions under which these gains occur.

### 4.1. Experimental Setup

Datasets. We evaluate on four multi-hop QA benchmarks, namely 2WikiMultiHopQA ([Ho et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib4)), HotpotQA ([Yang et al., 2018](https://arxiv.org/html/2611.04625v1#bib.bib3)), MuSiQue ([Trivedi et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib5)), and ConcurrentQA ([Arora et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib11)). Their annotated supporting documents define the target evidence sets. Dataset and evaluation details are provided in Appendix [A.1](https://arxiv.org/html/2611.04625v1#A1.SS1 "A.1. Experimental Setup ‣ Appendix A Additional Experimental Details ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution"). Model and training settings appear in Appendix [A.2](https://arxiv.org/html/2611.04625v1#A1.SS2 "A.2. Implementation Details ‣ Appendix A Additional Experimental Details ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution").

Evaluation metrics. For answer generation, we report LLM-Acc, the fraction of answers accepted by an LLM judge, and Contain, the fraction of generated answers containing the normalized gold answer string. For retrieval budget $k$, document recall and full recall are

| (15) |  | $\displaystyle\operatorname{R@}k(x)$ | $\displaystyle=\frac{&#124;\widehat{D}_{k}(x)\cap D^{*}(x)&#124;}{&#124;D^{*}(x)&#124;},$ |  |
| ---- | --- | ------------------------------ | ------------------------------ | --- |
|      |  | $\displaystyle\operatorname{FR@}k(x)$ | $\displaystyle=\mathbb{I}[D^{*}(x)\subseteq\widehat{D}_{k}(x)],$ |  |

where $\mathbb{I}$ is the indicator function. Both metrics are averaged over questions with nonempty support sets; FR@$k$ measures complete recovery of the supporting set. We report results for each dataset and an unweighted macro average at $k=10$ and $k=30$ (Tables [2](https://arxiv.org/html/2611.04625v1#S4.T2 "Table 2 ‣ 4.2. Main Results ‣ 4. Additional Results ‣ Appendix A Additional Experimental Details ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")).

Retrieval comparisons. We compare R@$k$ and FR@$k$ only for methods whose final retrieval output is a ranked list of documents. Methods returning only graph structures (e.g., ToG ([Sun et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib28))) or text chunks without a document ranking are evaluated through downstream answer quality instead.

Baselines. Our retrieval baselines cover hierarchical retrieval with RAPTOR ([Sarthi et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib12)), query expansion with HyDE ([Gao et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib13)), and late-interaction retrieval with ColBERTv2 ([Santhanam et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib14)). The six graph retrieval baselines are G-Retriever ([He et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib15)), LightRAG ([Guo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib16)), GraphRAG ([Edge et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib17)), DALK ([Li et al., 2024](https://arxiv.org/html/2611.04625v1#bib.bib18)), HippoRAG 2 ([Gutiérrez et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib19)), and GFM-RAG ([Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)). Appendix [A](https://arxiv.org/html/2611.04625v1#A1 "Appendix A Additional Experimental Details ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution") provides retrieval results for each dataset.

Answer generation. We use Qwen3.5-9B for answer generation across all methods. Following LinearRAG ([Zhuang et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib20)), we report LLM-Acc and Contain using the definitions above. Paired outcomes show which questions gain or lose complete support at a fixed cutoff, whereas budget curves show how early complete support appears in a ranking. Together, they connect the aggregate retrieval improvements to the availability of a complete supporting set for individual questions.

## 5. Conclusion

We presented QueryFlow, a graph retrieval framework that supports multi-hop question answering through coupled evidence propagation and query evolution. Accumulated graph context updates a shared query state, which controls subsequent boundary inputs and relation features. Across four multi-hop QA benchmarks, QueryFlow improves macro R@10, FR@10, and LLM-Acc over GFM-RAG by 4.98, 8.40, and 11.6 percentage points, respectively. At a budget of five documents, it also exceeds this baseline’s full recall at ten documents. Macro LLM-Acc also improves by 8.0 points over LinearRAG. Query-state interventions and interface ablations support the contribution of feedback within QueryFlow. The results connect evolving query conditions to more complete evidence sets and stronger downstream answers.

## Appendix A Additional Experimental Details

### A.1. Experimental Setup

#### 2WikiMultiHopQA

This benchmark combines Wikidata relations with Wikipedia text to construct questions with explicit multi-hop reasoning paths ([Ho et al., 2020](https://arxiv.org/html/2611.04625v1#bib.bib4)). These annotations specify the intermediate relations linking a question to its answer, providing a structured basis for assessing evidence-set recovery.

#### HotpotQA

Questions draw on multiple Wikipedia documents and include comparisons between entities ([Yang et al., 2018](https://arxiv.org/html/2611.04625v1#bib.bib3)). Sentence-level supporting facts identify the evidence needed for an answer. We map these annotations to source documents to define the target evidence sets.

#### MuSiQue

MuSiQue composes single-hop questions into connected two- to four-hop questions ([Trivedi et al., 2022](https://arxiv.org/html/2611.04625v1#bib.bib5)). Intermediate answers link successive steps, reducing opportunities for disconnected reasoning and making subsequent evidence needs depend on earlier discoveries. We use the answerable examples.

#### ConcurrentQA

ConcurrentQA requires evidence from distinct public and private data distributions ([Arora et al., 2023](https://arxiv.org/html/2611.04625v1#bib.bib11)). We use the supplied documents as a shared retrieval collection to evaluate evidence recovery across heterogeneous sources with the same document-ranking interface.

#### Evaluation subsets.

Following GFM-RAG ([Luo et al., 2025](https://arxiv.org/html/2611.04625v1#bib.bib8)), LinearRAG ([Zhuang et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib20)), and Relink ([Huang et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib56)), we use fixed evaluation subsets. Matching LinearRAG’s reference question lists to source records yields 1,000 questions each for 2WikiMultiHopQA and HotpotQA, with HotpotQA drawn from distractor validation. For MuSiQue, we match the reference list to records in the answerable validation split. HotpotQA and MuSiQue are shuffled with seed 42 before matching; list membership determines selection. ConcurrentQA uses all 1,600 validation questions. Input sets are shared across methods. Retrieval metrics are averaged over questions with nonempty support sets (Section [4.1](https://arxiv.org/html/2611.04625v1#S4.SS1 "4.1. Experimental Setup ‣ 4. Experiments ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")).

#### Retrieval corpora.

Supporting and distractor documents from the selected examples form each benchmark’s retrieval corpus. Table [5](https://arxiv.org/html/2611.04625v1#A1.T5 "Table 5 ‣ Retrieval corpora. ‣ A.1. Experimental Setup ‣ Appendix A Additional Experimental Details ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution") reports selected input records and corpus sizes after preprocessing. Each question is evaluated against this collection, with $k$ limiting the number of returned documents. Original support annotations define the target evidence sets.

#### Training data and supervision.

We use 20,000 examples and their associated content from each of 2WikiMultiHopQA, HotpotQA, and MuSiQue, totaling 60,000 training examples. Entity labels $y_{i}$ are derived from these training datasets. The graph interface is defined in Section [3.1](https://arxiv.org/html/2611.04625v1#S3.SS1 "3.1. Evidence Graph and Query Grounding ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution"). Extraction, normalization, linking, grounding, and document-to-entity label construction are detailed in the supplementary code.

### A.2. Implementation Details

#### Model architecture.

The frozen all-mpnet-base-v2 encoder supplies precomputed 768-dimensional question and relation embeddings, linearly projected to $d=512$. The propagation operator uses the NBFNet formulation ([Zhu et al., 2021](https://arxiv.org/html/2611.04625v1#bib.bib6)). The retriever uses $L=6$ layers with 512 hidden units, DistMult messages, sum aggregation, residual connections, layer normalization, and ReLU. The query controller also has 512-dimensional states. The full model enables both feedback interfaces with $\alpha=1$, attention temperature 1, and query-update dropout 0.

#### Optimization and hardware.

We train the retriever and query controller from random initialization on a single NVIDIA A100 using AdamW, learning rate $10^{-5}$, batch size one, gradient norm clipping at 1.0, and seed 1024. Activation checkpointing reduces propagation memory; the text encoder remains frozen.

#### Answer generation and judgment.

All methods generate answers with Qwen3.5-9B. Following LinearRAG ([Zhuang et al., 2026](https://arxiv.org/html/2611.04625v1#bib.bib20)), LLM-Acc records LLM judge acceptance; Contain checks for the normalized gold answer. Prompts, context handling, decoding, judge configuration, and output parsing are detailed in the supplementary code.

## Appendix B Training Objective and Retrieval Algorithm

### B.1. Document Evidence Readout

Default entity scoring uses $q_{0}$ during both training and retrieval. Intermediate query updates influence document ranking through the final entity representations $H_{L}$.

#### Aggregation over all entities.

Softplus preserves entity ordering and yields positive contributions $\mathbf{v}$. With $f_{i}=\sum_{j}A_{ij}$ and $w_{i}^{\mathrm{doc}}=1/f_{i}$ for $f_{i}>0$ (zero otherwise), the document scores are

| (16) |  | $\mathbf{d}=A^{\top}\!\left(\mathbf{w}^{\mathrm{doc}}\odot\mathbf{v}\right).$ |  |
| ---- | --- | ------------------------------ | --- |

Here $A\in\{0,1\}^{&#124;V&#124;\times&#124;D&#124;}$ and $\mathbf{d}\in\mathbb{R}^{&#124;D&#124;}$. All entities contribute; the top $k$ scores define $\widehat{D}_{k}(x)$. Paired propagation interventions keep the scorer and readout fixed.

### B.2. Entity-Level Training Objective

Training masks $y\in\{0,1\}^{&#124;V&#124;}$ define positives $P=\{i:y_{i}=1\}$ and negatives $N=\{i:y_{i}=0\}$. Binary and listwise losses supervise the graph and query controller.

#### Entity relevance objective.

Let $p_{i}=\sigma(s_{i})$, where $s_{i}$ is computed using the anchored scorer in Eq. ([10](https://arxiv.org/html/2611.04625v1#S3.E10 "In 3.4. Document Readout and Learning ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")). The binary cross-entropy for entity $i$ is

| (17) |  | $\ell_{i}=-y_{i}\log p_{i}-(1-y_{i})\log(1-p_{i}).$ |  |
| ---- | --- | ------------------------------ | --- |

Positive weights are uniform; negative weights depend on current logits,

| (18) |  | $\omega_{i}=\begin{cases}&#124;P&#124;^{-1},&i\in P,\\ \displaystyle\operatorname{sg}\!\left(\frac{\exp(s_{i}/T)}{\sum_{j\in N}\exp(s_{j}/T)}\right),&i\in N.\end{cases}$ |  |
| ---- | --- | ------------------------------ | --- |

Here $T=0.2$, and $\operatorname{sg}$ stops gradients through the negative weights. Negative entities with higher scores receive greater weight, concentrating the classification loss on negatives that the retriever currently ranks highly. The weighted binary loss is

| (19) |  | $\mathcal{L}_{\mathrm{BCE}}=\frac{\sum_{i\in V}\omega_{i}\ell_{i}}{\sum_{i\in V}\omega_{i}}.$ |  |
| ---- | --- | ------------------------------ | --- |

ListCE (Eq. ([13](https://arxiv.org/html/2611.04625v1#S3.E13 "In 3.4. Document Readout and Learning ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")), $\varepsilon=10^{-5}$) normalizes sigmoid probabilities over entities and averages negative log mass over all positives, excluding empty targets. The combined loss in Eq. ([14](https://arxiv.org/html/2611.04625v1#S3.E14 "In 3.4. Document Readout and Learning ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution")) is averaged over questions in each batch.

Aggregation of entity scores into document scores and document ranking are performed at inference time, outside the entity-level training objective. The query controller is trained through its influence on subsequent graph propagation and final entity scores; the supporting-document sets define the downstream evaluation targets.

### B.3. Retrieval Procedure

Algorithm [1](https://arxiv.org/html/2611.04625v1#alg1 "Algorithm 1 ‣ B.3. Retrieval Procedure ‣ Appendix B Training Objective and Retrieval Algorithm ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution") applies $L$ propagation layers with query updates between successive layers before ranking documents. The default $\alpha=1$ applies the gated increment before normalization; $\alpha=0$ fixes the query without changing learned propagation parameters.

At layer $l$, propagation first computes $H_{l}$ under $q_{l-1}$. When $l<L$, the updated entity states are summarized to form $q_{l}$, which conditions the next layer. The default scorer combines $H_{L}$ with $q_{0}$. The $q_{L}$ variant adds the terminal update defined in Section [3.3](https://arxiv.org/html/2611.04625v1#S3.SS3 "3.3. Graph-Conditioned Query Evolution ‣ 3. Method ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution") and substitutes $q_{L}$ in the scorer. Graph structure, grounding, and document associations remain fixed.

*Algorithm 1  QueryFlow with the default $q_{0}$ readout*

## Appendix C Readout Analysis

We compare aggregation over all entities with two truncated entity readouts, document-aware entity MMR ([Carbonell and Goldstein, 1998](https://arxiv.org/html/2611.04625v1#bib.bib10)) and relevance-based Top-20 selection. All three use the same propagated entity representations and reciprocal document frequency weighting.

*Table 8. Document readout comparison. Macro retrieval scores across four datasets (%).*

| Readout                | R@10  | FR@10 | R@30  | FR@30 |
| ---------------------- | ----- | ----- | ----- | ----- |
| MMR Top-20             | 80.48 | 67.84 | 85.31 | 74.72 |
| Top-20 (no MMR)        | 80.57 | 67.79 | 84.87 | 73.90 |
| All entities (default) | 81.93 | 70.38 | 87.12 | 77.78 |

Aggregation over all entities improves complete evidence recovery. The default readout exceeds both truncated alternatives on all four metrics in Table [8](https://arxiv.org/html/2611.04625v1#A3.T8 "Table 8 ‣ Appendix C Readout Analysis ‣ QueryFlow: Multi-Hop Graph Retrieval with Adaptive Query Evolution"). Relative to MMR Top-20, the gains are 2.54 and 3.07 percentage points in FR@10 and FR@30. Aggregating every entity contribution lets documents receive relevance signals distributed beyond a small selected subset, providing a mechanism for retaining complementary evidence. Within the truncated alternatives, MMR improves R@30 and FR@30 by 0.44 and 0.82 points, with mixed but small differences at $k=10$ ($-0.09$ R@10 and $+0.05$ FR@10).

Reciprocal weighting preserves each entity’s total contribution. For $f_{i}>0$, summing $A_{ij}v_{i}/f_{i}$ over documents yields $v_{i}$. Summing the complete document score vector gives

| (20) |  | $\sum_{j=1}^{&#124;D&#124;}d_{j}=\sum_{i\in V}w_{i}^{\mathrm{doc}}v_{i}\sum_{j=1}^{&#124;D&#124;}A_{ij}=\sum_{i\in V:f_{i}>0}v_{i}.$ |  |
| ---- | --- | ------------------------------ | --- |

Document associations redistribute each entity’s score across its source documents. An entity appearing in one document contributes its full score there; one appearing in several documents divides that contribution equally among them. This property controls how graph relevance transfers to documents without selecting a fixed number of entities. Each document can still accumulate contributions from multiple entities, so its rank depends on their combined relevance and document frequencies. The weighting acts on entity frequency rather than normalizing by document length.
